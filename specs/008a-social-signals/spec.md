# Feature Specification: Typing-индикатор, «был в сети», отображаемые имена и per-chat звук

**Feature Branch**: `008a-social-signals`

**Created**: 2026-10-08

**Status**: Approved

**Input**: User description: "Функциональность прототипа tmp/chats.html, не вошедшая в 008 из-за необходимости расширения API и realtime-событий. (1) Typing-индикатор: собеседник видит «X печатает…» (в группах — с именем конкретного участника) с дебаунсом начала/завершения; сигнал эфемерный, через realtime только участникам чата, не персистентен. (3) Отображаемые имена: пользователь задаёт имя профиля (displayName, редактирование в «Мой профиль»); контакт можно переименовать персонально (alias поверх профильного имени); инициалы аватаров — из имени с фолбэком на username; отображаемые имена используются в списках чатов/контактов, группах и поиске пользователей. Все изменения API — аддитивные (новые поля и события в публичном OpenAPI-контракте), обратная совместимость сохраняется. Поиск по сообщениям в фичу не входит (остаётся в 013)."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Отображаемые имена: имя профиля, персональный alias, инициалы (Priority: P1)

Пользователь задаёт себе имя профиля (displayName) в модальной форме «Мой профиль» (008) — вместо «только username» у пользователя появляется человекочитаемое имя, которое видят собеседники во всех списках: «Чаты», «Контакты», участники групповых чатов и результаты поиска пользователей. displayName опционален: не задан — везде отображается username (текущее поведение, обратная совместимость). Помимо этого, любой свой контакт пользователь может переименовать персонально (alias): новое имя видно только переименовавшему на всех его поверхностях и лежит «поверх» профильного имени; сам контакт и остальные пользователи продолжают видеть профильное имя. Сброс alias возвращает отображение к профильному имени. Единая цепочка разрешения отображаемого имени: alias (личный) → displayName профиля → username. Инициалы аватаров (008) строятся из отображаемого имени с фолбэком на username; сортировка и фильтрация контактов используют отображаемые имена.

**Why this priority**: Имя — фундамент идентичности в мессенджере: оно появляется на каждой поверхности (списки, группы, поиск) и используется остальными сигналами фичи — typing-индикатор в группе показывает имя конкретного участника (US2); без имён этот сценарий деградирует до username. Срез полностью самостоятелен: тестируется выставлением имени и переименованием контакта на всех поверхностях.

**Independent Test**: Два пользователя: первый задаёт displayName «Мария» в «Мой профиль», второй переименовывает первого в alias «Маша» у себя. Проверяется: у второго отображается «Маша» в «Чатах», «Контактах», участниках общей группы; у третьего пользователя и у самой Марии — «Мария»; после сброса alias у второго отображается «Мария»; у пользователя без displayName — username; инициалы аватаров соответствуют отображаемому имени.

**Acceptance Scenarios**:

1. **Given** пользователь без displayName, **When** открывает «Мой профиль», вводит имя «Мария» и сохраняет, **Then** имя сохраняется (подтверждение тостом, конвенция 008), а другие пользователи видят «Мария» вместо username в списке чатов, списке контактов, участниках групп и результатах поиска пользователей после обновления данных.
2. **Given** контакт в списке «Контакты», **When** пользователь выполняет «Переименовать» в контекстном меню «⋯» и вводит «Маша», **Then** только у переименовавшего на всех поверхностях (чаты, контакты, группы, поиск) отображается «Маша»; сам контакт и третьи лица изменений не видят; alias сохраняется на сервере и переживает перезагрузку и смену устройства.
3. **Given** alias установлен, **When** пользователь сбрасывает переименование, **Then** отображение возвращается к displayName контакта (а при его отсутствии — к username).
4. **Given** у пользователя нет displayName и нет alias, **When** отображаются любые поверхности, **Then** везде используется username — поведение идентично текущему (обратная совместимость, клиенты 008 работают без изменений).
5. **Given** попытка сохранить пустое/пробельное имя или имя длиннее лимита, **When** выполняется сохранение, **Then** выводится ошибка валидации, прежнее имя сохраняется; вводимый текст экранируется при отображении (008 FR-033).
6. **Given** сортировка и поиск в модальном окне «Контакты» (008 FR-011), **When** список отображается/фильтруется, **Then** сортировка идёт по отображаемому имени (alias → displayName), затем по username; фильтр — по подстроке отображаемого имени/username/email без учёта регистра.

### User Story 2 - Typing-индикатор «X печатает…» с дебаунсом (Priority: P1)

Пока участник набирает текст в композере чата, остальные участники видят индикатор «X печатает…», где X — отображаемое имя конкретного печатающего (в личном чате — собеседник, в группе — конкретный участник из US1). Индикатор появляется и исчезает с дебаунсом: сигнал начала отправляется не на каждый символ, а после первого введённого символа и далее не чаще фиксированного окна; завершение — при отправке сообщения, очистке поля или после окна молчания. Сигнал эфемерный: доставляется только живым участникам этого чата через существующий realtime-канал (№18), нигде не сохраняется, в истории отсутствует и не восстанавливается для тех, кто был офлайн; при пропаже клиента без сигнала завершения состояние самоистекает по серверному таймауту («вечно печатает» невозможно). Заблокированные пары (004 FR-020) сигналы не обменивают.

**Why this priority**: Типинг — сигнатурный «социальный» сигнал мессенджера из прототипа и самый ценовой realtime-элемент фичи; при этом он полностью самостоятелен: тестируется двумя пользователями в общем чате без остальных срезов (с фолбэком имени на username).

**Independent Test**: Два пользователя в общем чате: первый начинает набирать — у второго в течение 2 секунд появляется «Имя печатает…»; отправляет сообщение — индикатор исчезает; перестаёт печатать без отправки — индикатор исчезает по таймауту молчания; второй отключается от сети, первый печатает, второй возвращается — индикатора нет (эфемерность).

**Acceptance Scenarios**:

1. **Given** наблюдатель открыл общий личный чат, **When** собеседник вводит первый символ в композере, **Then** у наблюдателя не позднее 2 секунд (бюджет 95% — SC-001) отображается «{отображаемое имя} печатает…».
2. **Given** группа, **When** участник A печатает, **Then** остальные участники видят индикатор с именем именно A (разрешение имени — US1); **When** одновременно печатают два участника, **Then** отображается агрегированный индикатор: «{имя первого} и ещё {N-1} печатают…» (нормативный формат — contracts/ui-behavior.md §2.2).
3. **Given** индикатор активен, **When** печатающий отправляет сообщение или очищает поле, **Then** индикатор у участников исчезает не позднее 2 секунд (бюджет 95% — SC-001); **When** печатающий замолчал (без отправки), **Then** индикатор исчезает по истечении окна молчания.
4. **Given** печатающий печатает длительно (дольше окна повтора), **When** проходит очередное окно, **Then** сигнал начала повторяется (индикатор не «отвисает»), а не единожды.
5. **Given** наблюдатель был офлайн в момент набора, **When** он возвращается и открывает чат, **Then** индикатор отсутствует — пропущенный эфемерный сигнал не восстанавливается и не появляется из истории.
6. **Given** печатающий потерял связь/закрыл приложение без сигнала завершения, **When** проходит серверный таймаут состояния, **Then** индикатор у участников исчезает автоматически.
7. **Given** заблокированная пара в личном чате (004 FR-020), **When** один из пары пытается писать (композер неактивен, 008 FR-022), **Then** сигналы набора паре не отправляются и не доставляются.
8. **Given** клиент злоупотребляет сигналами (спам start/stop), **When** превышен флуд-лимит, **Then** избыточные сигналы отклоняются стандартным ответом лимита (конвенция контрактов), у наблюдателей дребезга индикатора нет.
9. **Given** пользователь печатает сам, **When** его другие устройства наблюдают чат, **Then** собственный набор нигде не отображается индикатором (механизм — серверная адресация: события набора не адресуются отправителю; contracts/realtime-events.md §1.1).

### User Story 3 - lastSeen: статус «Был в сети — {дата, время}» при офлайне (Priority: P2)

Когда собеседник офлайн, наблюдатель (в рамках политики приватности 007) видит вместо «слепого» офлайна человекочитаемый статус «Был в сети — {дата, время}» — в заголовке личного чата и в элементах списка «Контакты». Источник времени — последняя активность presence-канала пользователя (heartbeat/закрытие регистраций, TTL-модель 007): когда регистрации самоистекают или последнее соединение закрывается, время последней активности фиксируется и предоставляется клиентам в рамках той же аудитории видимости и тех же правил приватности, что и статус 007. Инкогнито (007) скрывает lastSeen: для аудитории такой пользователь остаётся просто «офлайн» без времени; блок-пары и посторонние не получают lastSeen ни через события, ни через API. При онлайне отображается «В сети» — без изменений (007). Нет данных (пользователь ни разу не был онлайн с момента появления фичи) и скрытые случаи отображаются единым нейтральным фолбэком «Был в сети — давно», неотличимым для наблюдателя.

**Why this priority**: lastSeen обогащает presence-сигнал 007 и переиспользует его приватность, но мессенджер полноценно работает и без него; интеграция с TTL-моделью требует аккуратности, но не блокирует остальные срезы, поэтому P2.

**Independent Test**: Собеседник выходит из сети (закрывает все устройства), наблюдатель дожидается перехода в «офлайн» (гистерезис 007) — в заголовке чата и «Контактах» появляется «Был в сети — {дата, время}» с корректным временем; собеседник включает инкогнито — время пропадает из всех поверхностей и API.

**Acceptance Scenarios**:

1. **Given** собеседник был онлайн, **When** его последний статус стал «офлайн» (все регистрации закрыты/истекли, гистерезис 007), **Then** наблюдатель видит «Был в сети — {дата, время}» в заголовке личного чата и в списке «Контакты» — время соответствует последней активности presence-канала в пределах точности TTL-модели 007.
2. **Given** собеседник в режиме «невидимки» (007), **When** аудитория запрашивает его статус, **Then** отображается «офлайн» без времени: lastSeen не раскрывается ни в UI, ни через API — 0 утечек.
3. **Given** данных о последней активности нет (никогда не был онлайн с момента фичи), **When** наблюдатель видит статус, **Then** отображается нейтральный фолбэк «Был в сети — давно», неотличимый от случаев «скрыто» (инкогнито, блок-пара, вне аудитории).
4. **Given** наблюдатель — посторонний или участник блок-пары, **When** запрашивает статус через API, **Then** lastSeen недоступен (нейтральный ответ политики 007, без различения причин).
5. **Given** офлайн-собеседник отобразил «Был в сети — …», **When** он снова подключается, **Then** статус возвращается к «В сети» (007), а при следующем уходе время обновляется.
6. **Given** наблюдатель в часовом поясе, отличном от пояса собеседника, **When** отображается lastSeen, **Then** время приводится к часовому поясу и локали наблюдателя в человекочитаемом формате по прототипу.

### User Story 4 - Переключатель звуковых оповещений чата (per-chat «звонок») (Priority: P3)

В заголовке окна чата появляется кнопка-«звонок» из макета 008, переключающая звуковые оповещения конкретного чата: «выкл» — входящие сообщения этого чата не звучат (визуальные уведомления — бейджи, лента, тосты — не затрагиваются), «вкл» — сигнал приёма работает по правилам 008 FR-028 (один сигнал на событие, коалесцирование пакетов массовой доставки, сигнала отправки нет). Настройка строго персональная (per-user-per-chat): другие участники о ней не знают. Значение хранится на сервере и синхронизируется между устройствами пользователя: переключение на одном устройстве тут же отражается на остальных через realtime; устройство, подключающееся или переподключающееся, получает актуальное состояние с сервера вместе с представлениями чатов. По умолчанию звук включён во всех чатах (паритет поведения 008).

**Why this priority**: Управление звуком — завершающий штрих уведомлений; работает поверх готового звука 008 и API-механики настроек, самостоятельно тестируется парой устройств, поэтому P3.

**Independent Test**: Пользователь с двумя устройствами приглушает чат кнопкой-«звонком» на первом — на втором кнопка меняет состояние без перезагрузки; входящее сообщение в приглушённый чат не звучит ни на одном устройстве, бейджи приходят; в другом чате звук звучит.

**Acceptance Scenarios**:

1. **Given** чат со звуком «вкл» (умолчание), **When** приходит входящее (открытый или фоновый чат), **Then** сигнал звучит по правилам 008 FR-028, кнопка-«звонок» в состоянии «вкл» (облик по прототипу).
2. **Given** открытый чат, **When** пользователь нажимает кнопку-«звонок», **Then** состояние переключается на «выкл» (визуально различимо по прототипу), операция идемпотентна; дальнейшие входящие этого чата не звучат — включая фоновые и пакеты массовой доставки после разрыва (0 звуков).
3. **Given** пользователь приглушил чат на устройстве A, **When** устройство B подключено к realtime-каналу, **Then** состояние кнопки и поведение звука на B обновляются без перезагрузки не позднее 2 секунд.
4. **Given** устройство переподключается (вход, реконнект), **When** загружаются представления чатов, **Then** состояние звука каждого чата соответствует серверному значению.
5. **Given** звук чата выключен, **When** приходят визуальные уведомления (бейдж непрочитанных, пузырь в ленте), **Then** они работают без изменений — настройка влияет только на звук.
6. **Given** частые переключения кнопкой, **When** превышен флуд-лимит операции, **Then** возвращается стандартный ответ лимита, последнее устойчивое состояние остаётся консистентным на всех устройствах.

### Edge Cases

- Печатающий закрыл приложение/потерял сеть без сигнала завершения — состояние набора самоистекает по серверному таймауту; наблюдатель не видит «вечного печатает» (US2 AC6).
- Наблюдатель открыл чат уже после прихода сигнала набора (был в другом чате) — индикатор может не отображаться до следующего сигнала (окна повтора); эфемерность не гарантирует доставку «задним числом» — это не ошибка.
- Реконнект наблюдателя посреди набора — уже показанный индикатор пропадает (состояние не реплеится), при продолжении набора появится снова по следующему сигналу.
- Отправка отклонена валидацией (пустой текст) — сигнал завершения всё равно отправляется: попытка отправки = завершение набора.
- Блокировка в паре включена в момент набора — сигналы не доставляются в обе стороны (семантика 004 FR-020 распространена на новые события).
- displayName из одних пробелов или пустое после trim — отклоняется валидацией при сохранении.
- Совпадающие displayName/инициалы у разных пользователей — допустимо (008 edge); различие обеспечивается username в контексте.
- Очень длинные displayName/alias — усечение с многоточием в списках, полный текст во всплывающей подсказке (конвенция 008).
- Unicode-имена (кириллица, латиница, эмодзи) — инициалы строятся по единому правилу прототипа (первые символы первых двух слов); «тофу» и подмена шрифта недопустимы (008 SC-006).
- Alias и удаление контакта — alias привязан к контакту и удаляется вместе с ним; повторное добавление контакта начинает с профильного имени.
- Alias и удаление чата — alias живёт на контакте, а не на чате: удаление/пересоздание чата переименование сохраняет (008 FR-013: «Удалить чат» контакт сохраняет).
- Переименование контакта, не являющегося участником ни одного чата, — alias сохраняется и отображается в «Контактах».
- lastSeen при падении инстанса (007 US3) — время фиксируется по последней активности регистраций; погрешность в пределах TTL регистрации + гистерезис 007 (≈ 2,5 минуты), «точность до секунды» не гарантируется.
- Мультидевайс lastSeen — фиксируется время активности последнего живого подключения пользователя (любого устройства).
- Граница суток при форматировании lastSeen («сегодня»/«вчера», переход полночи в поясах наблюдателя и собеседника) — отображение сходится к человекочитаемому формату наблюдателя без противоречий (правило фиксируется по прототипу в plan).
- Инкогнито при живых подключениях — 007 замораживает статус «офлайн» для аудитории; lastSeen также скрыт целиком (не «время включения инкогнито»).
- Факт свежего сообщения от «невидимки» сам по себе раскрывает активность — вне контроля presence-политики; политика касается только данных присутствия (lastSeen-поле и события).
- Звук и запрет автозвука браузером до первого действия пользователя — молчаливый пропуск без ошибок (008 FR-028), состояние настройки не меняется.
- Переключение звука при недоступной сети — операция серверная: без сети не выполняется (ошибка), локального «опережающего» переключения с последующей синхронизацией в v1 нет.
- Приглушение группового чата — действует как для личных: один переключатель на весь чат, индивидуальные настройки «по участникам» вне объёма.
- Первое включение фичи у существующих пользователей — displayName/alias не заданы (username), звук всех чатов «вкл», lastSeen начинает накапливаться с момента развёртывания (ретроспективного времени нет).

## Requirements *(mandatory)*

### Functional Requirements

Отображаемые имена:

- **FR-001**: Система MUST позволять аутентифицированному пользователю задавать и изменять имя профиля (displayName) в модальной форме «Мой профиль» (008): поле опционально, пустое значение эквивалентно «имя не задано» (отображение по username). Валидация MUST отклонять пустые/пробельные значения и значения сверх лимита длины (значение фиксируется в API-контракте; разумный дефолт — до 64 символов после trim); успешное сохранение подтверждается уведомлением (конвенция тостов 008).
- **FR-002**: displayName MUST передаваться новым опциональным полем во всех публичных представлениях пользователя: элементы списков «Чаты» и «Контакты», собеседник личного чата, участники групповых чатов, результаты поиска пользователей. Отсутствие поля или значения MUST оставлять текущее поведение (username) — клиенты, не знающие нового поля, работают без изменений (обратная совместимость).
- **FR-003**: Система MUST позволять пользователю персонально переименовывать свои контакты (alias): действие доступно из контекстного меню контакта «⋯» в модальном окне «Контакты» (новый пункт «Переименовать» рядом с действиями 008 FR-013); alias виден только переименовавшему на всех его поверхностях (чаты, контакты, участники групп, поиск) и не затрагивает отображение у самого контакта и третьих лиц; alias хранится на сервере per-user и переживает сессии/устройства; сброс alias возвращает отображение к displayName (→ username). Единая цепочка разрешения отображаемого имени: alias → displayName → username; валидация — как у FR-001.
- **FR-004**: Инициалы аватаров (008 FR-024) MUST строиться из отображаемого имени по цепочке FR-003 с фолбэком на username; детерминированный цвет аватара MUST оставаться производным от стабильного идентификатора (username пользователя / названия группы) — переименование не перекрашивает аватар; форма и палитра — 008 без изменений.
- **FR-005**: Сортировка и поиск MUST использовать отображаемые имена: сортировка контактов «по отображаемому имени, затем по username» (008 FR-011) — по цепочке FR-003; фильтрация в «Контактах» — по подстроке отображаемого имени/username/email без учёта регистра; семантика поиска пользователей (точное совпадение username/email, 004 №19) НЕ меняется — отображаемые имена влияют только на представление результатов, серверный поиск по displayName в объём фичи не входит.

Typing-индикатор:

- **FR-006**: Клиент MUST отправлять сигналы набора текста (начало/завершение) с дебаунсом: сигнал начала — после первого введённого символа и далее не чаще одного раза в фиксированное окно повтора (значения фиксируются в API-контракте); сигнал завершения — при отправке сообщения, очистке поля и истечении окна молчания; сигналы привязаны к композеру конкретного чата. Состояние композера «заблокирован» (008 FR-022) отправку сигналов исключает.
- **FR-007**: Система MUST доставлять сигналы набора только текущим участникам этого чата через существующий realtime-канал пользователя (№18, конвенция 004) новыми типами событий. Сигнал эфемерный: MUST NOT сохраняться в персистентном хранилище, MUST NOT попадать в историю сообщений и синхронизацию пропущенных (005), MUST NOT восстанавливаться подключившимся/переподключившимся клиентам. Серверное состояние набора MUST автоматически истекать по таймауту при отсутствии сигналов продления/завершения (обрыв, падение клиента) — «вечное печатает» исключено; параметры дебаунсов и таймаута фиксируются в контракте.
- **FR-008**: Клиенты MUST отображать индикатор «{имя} печатает…» в окне чата: имя — по цепочке разрешения FR-003 (в группе — имя конкретного печатающего участника); появление — не позднее 2 секунд после события; исчезновение — по сигналу завершения, отправке сообщения или истечении окна молчания; несколько одновременно печатающих — агрегированное отображение (имя + счётчик); собственный набор на своих устройствах не отображается. Заблокированные пары (004 FR-020) сигналы набора не обменивают в личных чатах (обе стороны, серверное подавление публикации); доставка в групповых чатах блокировками не фильтруется — паритет с 006 (chat.read / message.created).
- **FR-009**: Операции сигналов набора MUST ограничиваться флуд-лимитом на пользователя (защита от спама start/stop): превышение — стандартный ответ лимита контрактов (429 + Retry-After, конвенция 004); избыточные сигналы не порождают дребезга индикатора у наблюдателей.

lastSeen:

- **FR-010**: Presence-модель (007) MUST фиксировать время последней активности пользователя в presence-канале (жизненный цикл регистраций: heartbeat/закрытие/истечение TTL) и предоставлять его через API новым опциональным полем для офлайн-пользователей. Раскрытие lastSeen MUST подчиняться политике приватности 007 (FR-003/FR-007): только аудитория видимости; режим «невидимки» и блок-пары скрывают lastSeen целиком (значение «скрыто» неотличимо от «нет данных»); посторонним — нейтральный ответ. Точность времени — в пределах TTL-модели 007 (регистрация + гистерезис), фиксируется в контракте.
- **FR-011**: Клиенты MUST отображать статус офлайн-собеседника как «Был в сети — {дата, время}» в заголовке личного чата и в элементах списка «Контакты»; формат — человекочитаемый, локаль и часовой пояс наблюдателя, правила по прототипу (разумный дефолт: сегодня — только время, иначе — дата и время). Статус «онлайн» («В сети») — без изменений (007). Отсутствие или скрытие данных MUST отображаться единым нейтральным фолбэком «Был в сети — давно», неотличимым между причинами (нет данных / инкогнито / блок-пара / вне аудитории).

Переключатель звука per-chat:

- **FR-012**: Система MUST хранить на сервере персональную настройку звуковых оповещений для каждого чата пользователя (per-user-per-chat; умолчание — «включено») и предоставлять её в публичном API аддитивно (чтение — в представлениях чатов, изменение — отдельной операцией с флуд-лимитом и идемпотентностью). Настройка персональна: факт и значение для других участников не раскрываются.
- **FR-013**: Заголовок окна чата MUST содержать кнопку-«звонок» (облик — прототип 008) для переключения звука этого чата: состояние визуально различимо («вкл»/«выкл» по прототипу) и доступно с клавиатуры; действие доступно для личных и групповых чатов; повторные переключения идемпотентны.
- **FR-014**: Для чата с выключенным звуком звуковой сигнал приёма (008 FR-028) MUST отсутствовать на всех устройствах пользователя для всех входящих этого чата — включая фоновые и пакеты массовой доставки после разрыва; визуальные уведомления (бейджи, лента, тосты) MUST работать без изменений. Для чатов со включённым звуком правила 008 FR-028 сохраняются полностью (коалесцирование, отсутствие сигнала отправки, молчаливый пропуск при запрете автозвука).
- **FR-015**: Изменение настройки звука MUST синхронизироваться между устройствами пользователя в реальном времени (событие в собственный realtime-канал пользователя, №18) и MUST быть доступным подключающимся/переподключающимся клиентам с сервера (в представлениях чатов) — отображаемое состояние сходится к серверному на всех устройствах.

Контракт и наблюдаемость:

- **FR-016**: Все изменения публичного API MUST быть строго аддитивными — новые опциональные поля существующих представлений, новые операции и новые типы realtime-событий канала №18 — с сохранением обратной совместимости (конституция IV); TypeScript-типы фронтенда — из генерации контракта (конвейер 001).
- **FR-017**: Система MUST предоставлять наблюдаемость новых сигналов по образцу 007 FR-009: счётчики опубликованных/доставленных событий набора, подавленные флуд-лимитом сигналы, метрики операций настройки звука — достаточные для проверки Success Criteria в эксплуатации.

### Key Entities *(include if feature involves data)*

- **Отображаемое имя (displayName)**: опциональное профильное имя пользователя; публично возвращается во всех представлениях пользователей; пусто/отсутствует → отображение username.
- **Персональный alias контакта**: имя, которое пользователь лично дал своему контакту; видно только ему на всех его поверхностях; хранится на сервере per-user; поверх displayName; сброс — возврат к профильному имени.
- **Цепочка разрешения имени**: alias → displayName → username — единое правило отображения имён пользователей на всех поверхностях клиента.
- **Сигнал набора текста (typing)**: эфемерное состояние «участник X набирает текст в чате C»; живёт только в realtime-канале участников чата и серверной памяти с самоистечением; не персистентен.
- **lastSeen**: время последней активности presence-канала пользователя (heartbeat/закрытие регистраций); раскрывается только в рамках политики приватности 007; погрешность в пределах TTL-модели.
- **Настройка звука чата**: персональное per-user-per-chat предпочтение звуковых оповещений входящих; серверное, синхронизируется между устройствами пользователя; умолчание — включено.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 95% сигналов начала набора отображаются индикатором у участников открытого чата не позднее 2 секунд; после отправки сообщения/очистки поля индикатор исчезает не позднее 2 секунд у 95% участников (автоматизированный тест).
- **SC-002**: Эфемерность и адресация — 100% автоматизированных тестов приватности: сигналы набора и lastSeen не доставляются посторонним и блок-парам, не раскрываются через API, не восстанавливаются подключившимся клиентам; 0 утечек.
- **SC-003**: Серверное состояние набора самоистекает не позднее зафиксированного таймаута после пропадания клиента без завершения — 100% тестов; после самоистечения и завершения сессии 0 следов состояния в персистентном хранилище.
- **SC-004**: 100% поверхностей (список «Чаты», «Контакты», участники групп, поиск пользователей) отображают имя по цепочке alias → displayName → username после обновления данных; инициалы аватаров соответствуют отображаемому имени; существующие клиенты без нового поля отображают username без ошибок (автоматизированные + приёмочные проверки).
- **SC-005**: lastSeen отображается при офлайне собеседника в заголовке личного чата и списке «Контакты» в 100% приёмочных прогонов в рамках политики; отображаемое время расходится с фактической последней активностью presence-канала не более чем на TTL-модель 007 (регистрация + гистерезис); при инкогнито/блок-паре/вне аудитории — 0 раскрытий (SC-002).
- **SC-006**: Переключение звука чата отражается на других устройствах пользователя не позднее 2 секунд в 95% случаев; приглушённый чат воспроизводит 0 звуковых сигналов на всех устройствах — 100% автоматизированных тестов; визуальные уведомления работают без изменений.
- **SC-007**: Обратная совместимость: 0 breaking-изменений публичного контракта (автоматическое доконрактное сравнение, конвейер 001); все существующие автоматические проверки фич 004–008 проходят без изменения ожиданий.
- **SC-008**: Новые сигналы укладываются в конституционные бюджеты (принцип II): расчёт нагрузки typing-событиями (частота × аудитория чата) приводится в plan.md; нагрузочный smoke с активным набором текста не деградирует доставку сообщений — Δp99 push ≤ 10% к базовому прогону (по образцу 007 SC-007); метрики FR-017 доступны.

## Assumptions

- Прототип `specs/008-chat-window-styling/design/chats.html` (версионированная копия `tmp/chats.html`) — нормативный эталон облика новых элементов: строка «X печатает…», статус «В сети» / «Был в сети — {дата, время}» с фолбэком «давно», кнопка-«звонок» в заголовке.
- Механизмы фич 002–008 доступны и переиспользуются: realtime-канал №18 (конвенция at-most-once, игнорирование неизвестных `event:`), presence-модель 007 (регистрации с TTL 90 c, heartbeat №37, гистерезис 45 c, аудитория видимости, инкогнито №38), контакты и блокировки 004, UI-паттерны и дизайн-система 008.
- Транспортные и контрактные детали — решения plan-раунда, фиксируются в публичном OpenAPI-контракте: форма операций сигналов набора, окно повтора начала и окно молчания, серверный таймаут состояния, лимит длины имён, точность lastSeen, схема события синхронизации звука. В спеке зафиксированы только наблюдаемые требования (дебаунс, эфемерность, адресация, приватность).
- В v1 не вводится отдельное realtime-событие об изменении displayName/alias (YAGNI): другие пользователи и другие устройства видят новые имена при следующем обновлении данных (рефетч списков/чата).
- alias существует только для личных контактов; персональное переименование групповых чатов вне объёма (название группы — общее, 006); alias удаляется вместе с удалением контакта (повторное добавление — с чистого листа) и сохраняется при удалении чата (alias принадлежит контакту).
- Цвет аватара остаётся производным от стабильного идентификатора (username/название группы, 008 FR-024); из отображаемого имени строятся только инициалы.
- lastSeen — время активности presence-канала (heartbeat/регистрации), а не «время последнего сообщения»; ретроспективных данных до развёртывания фичи нет (новые пользователи и существующие начинают «с нуля» — фолбэк «давно»).
- «Был в сети — давно» — единый нейтральный фолбэк, неотличимый между «нет данных» и «скрыто» (инкогнито/блок-пара/вне аудитории) — продолжение принципа унификации `unknown` из 007.
- Формат lastSeen — русская локаль и часовой пояс наблюдателя; дефолт «сегодня — только время, иначе — дата и время» уточняется по прототипу в plan; i18n не вводится (решение 008).
- Звук по умолчанию включён во всех чатах (паритет 008 FR-028 «всегда включено»); настройка строго серверная: переключение без сети не выполняется (ошибка операции), локальная офлайн-очередь переключений не вводится (YAGNI).
- Индикатор набора отображается в окне чата; доставка сигналов «задним числом» открытым позже чатам и реплей при реконнекте не гарантируются (эфемерность).
- Поиск по сообщениям — вне объёма (фича 013); серверный поиск пользователей по displayName — вне объёма (YAGNI, возможная будущая фича).
- Встраиваемый виджет (015, ROADMAP) переиспользует те же контрактные поля, события и клиентские модули; отдельная widget-работа в 008a не требуется (архитектурная единообразность SPA/виджет — конституция IV, верифицируется в 015).
- Изменение displayName самим пользователем отражается у него немедленно (после сохранения); у остальных — по правилам рефетча (см. выше) — осознанное упрощение v1.
