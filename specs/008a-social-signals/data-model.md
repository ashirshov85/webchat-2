## 1. Durable-модель (PostgreSQL, миграция V16)

### 1.1 `users` — + `display_name`

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `display_name` | `VARCHAR(64)` NULL | `display_name IS NULL OR (char_length(btrim(display_name)) BETWEEN 1 AND 64)` | Профильное имя (FR-001). NULL = «не задано» → отображение по `username`. Значение пишется после серверного trim. |

- **Валидация**: сервис отклоняет пустые/пробельные и >64 симв. после trim → 400 `invalid_display_name` (FR-001/US1 AC5).
- **Жизненный цикл**: set/clear через №39 (`PUT /users/me/profile`); NULL при создании (все существующие пользователи — «не задано», edge-кейс первого включения).
- **Неизменяемое**: цвет аватара остаётся производным от `username` (FR-004).

### 1.2 `user_contacts` — + `alias`

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `alias` | `VARCHAR(64)` NULL | `alias IS NULL OR (char_length(btrim(alias)) BETWEEN 1 AND 64)` | Персональное имя контакта у владельца строки (FR-003). NULL = нет alias. |

- **Ключ** — существующий PK `(owner_id, contact_user_id)`: alias по определению per-user-per-contact.
- **Валидация**: как у displayName → 400 `invalid_alias`.
- **Жизненный цикл**: set/reset через №40 (`PUT /contacts/{userId}/alias`, null = сброс); **удаляется вместе с контактом** (№22 — строка уходит целиком; повторное добавление — с чистого листа, edge-кейс); **переживает удаление чата** (не привязан к чатам, edge-кейс); работает для контактов без чатов (edge-кейс).
- **Приватность**: читается только владельцем (`owner_id = me`) во всех проекциях; сам контакт и третьи лица не получают поле никогда (FR-003).

### 1.3 `chat_participants` — + `sound_enabled`

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `sound_enabled` | `BOOLEAN NOT NULL DEFAULT TRUE` | — | Персональный переключатель звука чата (FR-012). Умолчание TRUE — паритет 008 «всегда включено». |

- **Ключ** — существующий PK `(chat_id, user_id)`: ровно per-user-per-chat.
- **Жизненный цикл**: set через №42 (`PUT /chats/{chatId}/sound`, идемпотентно, флуд 30/мин); переживает скрытие/удаление чата (строка участника сохраняется, 008 FR-013); новое участие (создание/ensure чата) — TRUE.
- **Приватность**: значение и факт настройки читаются только владельцем (`soundEnabled` в №12/№13 для себя; событие `chat.sound.updated` — только в собственный канал).

## 2. Эфемерная модель (Redis, TTL; SC-003 — 0 следов в PG)

### 2.1 Состояние набора текста (typing)

**Сущность**: `TypingState {chatId, userId, expiresAt}` — «участник userId набирает текст в чате chatId до expiresAt».

| Ключ | Тип | Содержимое | TTL/истечение |
|---|---|---|---|
| `typing:active:{chatId}` | ZSET | member=`userId`, score=`expiresAtMs` | poller-чистка по score; ключ-строк TTL = серверный таймаут + буфер (страховка мусора) |
| `typing:watch` | ZSET (глобальный) | member=`{chatId}:{userId}`, score=`expiresAtMs` | ZREM poller'ом при истечении/stop |

- **Операции** (порт `TypingStore`):
  - `start(chatId, userId, ttl)`: ZADD в оба ZSET (продлевает) — по `start`-сигналу №41;
  - `stop(chatId, userId)`: ZREM из обоих — по `stop`-сигналу, отправке сообщения (сервер гасит состояние отправителя при INSERT сообщения) и при удалении участника из чата;
  - `dueExpired(batch)`: истёкшие пары → для каждой publish `typing.stopped` + ZREM (poller `TypingTransitionScheduler`, тик 1 с, батч ≤1000).
- **Константы** (фиксируются контрактом, конфиг `chats.typing.*`): серверный таймаут состояния **8 с**; окно повтора клиента **3 с**; окно молчания клиента 5 с; страховый клиентский таймаут 10 с.
- **Переходы состояния** (state machine):

```text
[нет состояния] --start(№41)--> ACTIVE(expiresAt=now+8s)
ACTIVE --start(№41)--> ACTIVE(expiresAt=now+8s)        (продление состояния; publish typing.started — на каждом валидном start, см. сноску *)
ACTIVE --stop(№41)--> [нет]           → publish typing.stopped участникам без отправителя
ACTIVE --отправка сообщения(№16)--> [нет] → publish typing.stopped
ACTIVE --истечение score (poller)--> [нет] → publish typing.stopped (AC6, метрика state_expired)
ACTIVE --expiry ключа-строки (страховка)--> [нет] (без публикации; компенсируется клиентским 10с-таймаутом)
```

\* публикация `typing.started` наблюдателям происходит при каждом валидном `start`-запросе (продление = повтор события — AC4 «индикатор не отвисает»); дребезг исключён клиентским окном 3 с и серверным флуд-лимитом 60/мин (AC8).

- **Инварианты**: не персистентен (нет PG/истории/sync — FR-007); доставляется только живым участникам чата минус отправитель (AC9); блок-пара DIRECT — подавление публикации в обе стороны (AC7); подключившийся клиент состояние не читает (нет API чтения — AC5).

### 2.2 lastSeen (расширение presence-модели 007)

**Сущность**: время последней активности presence-канала пользователя.

| Ключ | Тип | Содержимое | TTL |
|---|---|---|---|
| `presence:lastseen:{userId}` | STRING | epoch ms (из Redis `TIME`) | 30 дней |

- **Точки записи** (в существующих Lua-ногах `RedisPresenceStore`, атомарно с текущими операциями): `REGISTER` (открытие соединения), `RENEW` (heartbeat №37), `UNREGISTER` (закрытие), `CLEAR_SESSION` (logout №7). Истечение регистрации (reap) отдельной записи не делает — остаётся stamp последнего heartbeat.
- **Точность** (SC-005): штатное закрытие — точное; обрыв/TTL-истечение — погрешность ≤ TTL 90 c + гистерезис 45 c + poller 1 c ≈ 137 с (≈ 2,5 мин, допуск спеки).
- **Чтение**: пакетно в `SNAPSHOT` (№36) и при offline-переходе (событие `presence.updated`).
- **Правила раскрытия** (единый алгоритм для API и событий):

```text
lastSeenAt раскрывается ⇔ status = offline
                          ∧ наблюдатель ∈ аудитория видимости 007 (JdbcVisibilityAudienceReader)
                          ∧ subject не в инкогнито (presence_hidden = false)
                          ∧ ключ существует (был онлайн после развёртывания фичи)
иначе — поле ОТСУТСТВУЕТ (нейтрально: «нет данных» ≡ «скрыто» ≡ «посторонний» ≡ «блок-пара»)
```

- Мультидевайс: ключ один на пользователя, пишет любое живое подключение (edge-кейс).
- Ретроспективы нет: до развёртывания фичи данных не существует → фолбэк «давно» (edge-кейс).

## 3. Контрактные представления (изменения; полные схемы — contracts/api-contract.md)

| Схема | Новые поля | Источник |
|---|---|---|
| `PublicUser` | `displayName?: string` (opt) | `users.display_name` — профильное имя |
| `ContactView` | `alias?: string` (opt) | `user_contacts.alias` запросчика |
| peer-фрагмент №11/№12/№13 | `displayName?`, `alias?` (opt) | PublicUser + alias запросчика к peer |
| `GroupMember.user` (№28) | `displayName?`, `alias?` (opt) | PublicUser + alias запросчика к участнику |
| №19 результат поиска | `displayName?`, `alias?` (opt) | PublicUser + alias (если найденный — контакт запросчика) |
| `ChatView`, `ChatListItem` | `soundEnabled?: boolean` (opt, сервер выставляет всегда) | `chat_participants.sound_enabled` запросчика |
| `PresenceStatusItem` (№36) | `lastSeenAt?: string` date-time (opt) | §2.2, только offline + аудитория + не инкогнито |
| `PresenceUpdatedEvent` (№18) | `lastSeenAt?: string` (opt) | то же, при offline-переходе в рамках аудитории |

**Цепочка разрешения отображаемого имени** (единая, клиентская функция `resolveDisplayName`):

```text
alias (личный, только у владельца) → displayName профиля → username
```

- Применяется на всех поверхностях: список «Чаты» (peer/группа), «Контакты», участники групп, поиск, typing-индикатор (имя печатающего), инициалы аватаров; сортировка контактов — по цепочке, затем `username`; фильтр — подстрока в `[цепочка, username, email]` без регистра (FR-005).
- Серверная семантика сортировки/поиска не меняется (точное совпадение username/email, 004 №19).
- Обновление имён у третьих лиц — по рефетчу (списки/чат), без realtime-события (допущение спеки, YAGNI).

## 4. Сущность «сигнал набора» — сквозной поток данных

```text
Композер (chatId) --[первый символ / окно 3с]--> POST /typing {start}
  → гейты: auth → membership → флуд 60/мин → блок-пара (DIRECT, обе стороны)
  → TypingStore.start (ZSET, TTL 8с) → fanout typing.started {chatId, userId}
      → rt:user:{участник} (кроме отправителя) → SSE-кадр наблюдателю
Наблюдатель: presence имени (resolveDisplayName) → TypingRow «{имя} печатает…» ≤ 2с (SC-001)
Завершение: stop (отправка/очистка/молчание 5с) ИЛИ сообщение №16 ИЛИ poller-истечение 8с
  → fanout typing.stopped → индикатор скрыт (+страховочный клиентский таймаут 10с)
```

## 5. Неизменяемые инварианты целостности

- Сообщения/доставка/синхронизация 004–005: typing не участвует в PG-записях, cursor'ах и sync-дельтах — дубли/порядок/потери сообщений не затрагиваются (конституция III).
- `user_contacts.alias` никогда не возвращается не-владельцу; `sound_enabled` никогда не возвращается не-владельцу строки участника (приватность V).
- `lastSeenAt` при инкогнито отсутствует целиком — не «время включения инкогнито» (edge-кейс спеки).
- Валидационные отклонения (пустое/пробельное/длина) не меняют прежнее значение (US1 AC5).
