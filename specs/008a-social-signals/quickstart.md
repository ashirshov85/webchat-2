## Предусловия

- Запущены зависимости: `docker compose -f deploy/local/docker-compose.yml up -d` (PostgreSQL 17, Redis 7)
- Сборка backend: `./gradlew check` (из `backend/`, JDK 21)
- Фронтенд: `pnpm --dir frontend install`, контракт регенерирован (`pnpm --dir frontend generate:api` — после правки `contracts/openapi.yaml`)
- Контрактные гейты: `scripts/validate-contracts.sh` (vacuum + drift + oasdiff breaking = 0)
- Три тестовых пользователя (регистрация 002): alice, bob, carol; запущено backend + `pnpm --dir frontend dev` в двух/трёх браузерных профилях (мультидевайс-сценарии US4)

## Сценарии проверки (по User Stories спеки)

### US1 — Отображаемые имена (P1)

1. **Профильное имя**: alice → «Мой профиль» → поле «Имя» = `Мария` → Сохранить → тост `Профиль обновлён — Мария`.
   Ожидание: bob видит `Мария` (вместо username alice) в «Чатах» (после рефетча), «Контактах», участниках общей группы, поиске №19 по username/email; инициалы аватара — из `Мария`, цвет прежний (от username).
2. **Alias**: bob → «Контакты» → «⋯» → «Переименовать» → `Маша` → тост.
   Ожидание: `Маша` у bob на всех его поверхностях; carol и alice видят `Мария`; сброс (пустое значение формы) → снова `Мария`.
3. **Обратная совместимость**: пользователь без displayName/alias — везде username (как в 008); валидация: пробельное имя и >64 симв. отклоняются с ошибкой, прежнее значение сохраняется.

### US2 — Typing-индикатор (P1)

1. alice открыла общий чат с bob, начинает печатать → у bob ≤ 2 с `Мария печатает…` (лампы-точки, курсив).
2. alice отправляет сообщение → индикатор у bob исчезает; перестаёт печатать без отправки → исчезает по молчанию (5 с клиент / 8 с сервер).
3. Группа: печатают двое → `X и ещё 1 печатают…`; в группе показывается имя и аватар конкретного участника.
4. Эфемерность: bob отключается от сети, alice печатает, bob возвращается → индикатора нет.
5. Обрыв alice без stop (закрыть вкладку) → у bob индикатор самоистекает ≤ ~8 с + бюджет доставки (серверный таймаут).
6. Блок-пара: bob блокирует alice → сигналы не доставляются в обе стороны; композер заблокирован (008 FR-022).
7. Спам start/stop скриптом > 60/мин → 429 `flood_limit` + `Retry-After`, у наблюдателей дребезга нет.

### US3 — lastSeen (P2)

1. bob закрывает все устройства → после перехода в offline (гистерезис 007) alice видит `Был в сети — {HH:MM}` (сегодня) / `24 сентября, 16:20` в заголовке чата и «Контактах»; время в поясе/локали alice.
2. bob включает инкогнито → `lastSeenAt` исчезает из UI и API (в №36 поля нет) → `Был в сети — давно`.
3. Нет данных (новый пользователь ни разу не онлайн) → `Был в сети — давно` — неотличимо от скрытого (проверка неотличимости ответа №36: поле отсутствует в обоих случаях).
4. Посторонний carol вне аудитории → нейтральный ответ 007 (`unknown`/без поля) — 0 утечек.

### US4 — Per-chat звук (P3)

1. Устройство A и B пользователя alice открыты; A переключает «звонок» в чате с bob → B меняет состояние ≤ 2 с (событие `chat.sound.updated`); тост и «глухой щелчок».
2. bob пишет в приглушённый чат → 0 звука на обоих устройствах alice; бейдж/лента работают; сообщение в другом (неприглушённом) чате звучит.
3. Пакет массовой доставки после разрыва (sync 005) с входящими только в приглушённый чат → 0 звуков.
4. Переподключение устройства → состояние «звонков» из №12/№13 соответствует серверному; частые переключения > 30/мин → 429, консистентность последнего значения.

### Ручной замер перцентилей 95% / 2 с (SC-001, SC-006)

- **SC-001 появление**: ≥ 20 итераций «печатающий начинает ввод → появление индикатора у наблюдателя»; фиксировать время каждой итерации. Критерий: доля итераций ≤ 2 с ≥ 95%.
- **SC-001 исчезновение**: ≥ 20 итераций «отправка сообщения → исчезновение индикатора» — аналогично.
- **SC-006**: ≥ 20 переключений «звонка» на устройстве A → время до смены состояния на устройстве B; доля ≤ 2 с ≥ 95%.
- Протокол: итерации подряд, пауза ≥ 5 с между ними; результат заносится в таблицу (итерация, мс, pass/fail).

## Автоматизированная верификация

```bash
# Backend IT (Testcontainers; typing-окна ускорены профилем test)
./gradlew test --tests 'webchat.backend.chats.TypingIT'          # фрейминг/эфемерность/блок-пары/флуд/самоистечение/SC-001..003
./gradlew test --tests 'webchat.backend.chats.ChatSoundIT'       # идемпотентность/sync-событие/приватность/SC-006
./gradlew test --tests 'webchat.backend.users.ProfileDisplayNameIT'
./gradlew test --tests 'webchat.backend.contacts.ContactAliasIT' # SC-004
./gradlew test --tests 'webchat.backend.presence.PresenceLastSeenIT' # SC-002/SC-005
./gradlew check                                                   # весь набор 002–008 без изменений ожиданий (SC-007)

# Frontend
pnpm --dir frontend lint && pnpm --dir frontend typecheck
pnpm --dir frontend test          # vitest: names/typing/sound/header/contacts/profile
pnpm --dir frontend test:visual   # social-signals.spec.ts + перезахват затронутых базлайнов

# Контракт (SC-007)
scripts/validate-contracts.sh     # vacuum + generate:api drift + oasdiff breaking = 0 ERR

# Нагрузка (SC-008)
# k6 run load/k6/social-signals.smoke.js  (базовый прогон vs прогон с активным набором;
# критерий: Δp99 webchat_realtime_push_seconds ≤ 10%)
```
