# Quickstart: валидация фичи «Присутствие» (007)

**Date**: 2026-10-01 | Руководство проверки end-to-end; детали интерфейсов — [contracts/presence-api.md](./contracts/presence-api.md), [contracts/presence-events.md](./contracts/presence-events.md), модель — [data-model.md](./data-model.md).

## Предусловия

- Локальный стек: `deploy/local/docker-compose.yml` (PG 17, Redis 7) поднят; backend и frontend запускаются как в README репозитория.
- Два тестовых пользователя A и B с подтверждённым email (флоу 002), между ними есть личный чат (004 №11), у A есть B в контактах (004 №20).
- Тестовые окна: тест-профиль ужимает `presence`-параметры (TTL 90 c → 3 c, гистерезис 45 c → 2 c) — значения CI ниже используют их; против локального дефолта умножьте ожидания соответственно (137 c worst case: TTL 90 + гистерезис 45 + 2×poller 1 c — SC-003).

## Ручные сценарии (браузер: окно A — SPA, окно B — второе устройство/инкогнито-сессия)

### QS-1. Индикатор и realtime-обновление (US1, SC-001/SC-005)

1. A и B открывают мессенджер (SSE №18 подключён; в элементе B списка «Чаты», заголовке чата и списке «Контакты» у A — индикатор B).
2. B подключается (открывает приложение) → у A индикатор B зажигается «онлайн» ≤ 2 c, без перезагрузки; подпись/aria-метка озвучивает «онлайн» (clarify a11y).
3. B закрывает все устройства → после окна гистерезиса индикатор гаснет («офлайн»).
4. Мультидевайс: B открывает две сессии, закрывает одну → статус остаётся «онлайн» (SC-005).
5. A перезагружает страницу до первого снапшота → индикатор B нейтрален («неизвестно»), ложного «офлайн» нет; после загрузки — актуальное значение.

### QS-2. «Метро»-флап (US2, SC-002)

1. B онлайн; сеть B рвётся/восстанавливается DevTools'ом (offline/online) серией ≥ 10 раз, каждая пауза < окна гистерезиса.
2. У A — 0 смен индикатора за серию.
3. Единичный обрыв длиннее окна → ровно один переход «офлайн» и один возврат.

### QS-3. Самоистечение (US3, SC-003)

1. B «зависает» (kill браузера без закрытия вкладки / блокировка сети без disconnect) → heartbeat B прекращается.
2. Без явного logout у A индикатор B становится «офлайн» ≤ TTL + гистерезис (тест-профиль: ~5 c).

### QS-4. Приватность и «невидимка» (US4, SC-004)

1. Посторонний C (нет чата с B, нет в контактах): событие `presence.updated` о B не приходит в SSE C; №36 отвечает для B `unknown`.
2. B включает «невидимку» (№38 в настройках профиля) → A видит B «офлайн» (одно переключение), при этом B видит статусы A; после перелогина B режим сохранён.
3. A блокирует B (004) → пара не видит статусы друг друга (№36 → `unknown`, события не доставляются).

## Автоматизированная проверка

```bash
# backend: интеграционные сценарии фичи (мультидевайс, метро, self-expiry, приватность, снапшот, rev-merge)
./gradlew test --tests 'webchat.backend.presence.*'   # workdir backend/ (паттерн 002/003)

# frontend: rev-слияние, нейтральный индикатор, a11y-метка
pnpm --dir frontend test

# контракты: валидация + отсутствие breaking-изменений + drift типов
./scripts/validate-contracts.sh   # vacuum lint -e + oasdiff breaking-check (0.6.0 → 0.7.0 additive)

# нагрузочный smoke (SC-007): подключения + heartbeat + переключения; delivery-метрики messaging не деградируют
k6 run load/k6/presence.smoke.js
```

Ожидаемые исходы: зелёные прогоны; SC-001/SC-002/SC-003/SC-004/SC-005/SC-006 подтверждены CI-сценариями; smoke не показывает роста p99 доставки сообщений (Δp99 ≤ 10% к базовому прогону; полномасштабные пики — фича 016).
