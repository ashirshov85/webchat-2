# Data Model: Присутствие пользователей (007)

**Date**: 2026-10-01 | Спека: [spec.md](./spec.md) | Исследования: [research.md](./research.md)

Присутствие — производное, неисторическое состояние (FR-001): доменных таблиц в PG не появляется; durable-изменение — одна колонка настройки приватности. Живое состояние — структуры Redis с самоистечением.

## 1. Сущности

### 1.1 PresenceRegistration (Регистрация подключения)

Запись об одном живом SSE-подключении устройства/сессии к каналу №18.

| Поле | Тип | Описание |
|---|---|---|
| connectionId | UUID | Сгенерирован сервером при открытии SSE; виден клиенту в фрейме `connected`; идентификатор heartbeat'а (№37) |
| userId | UUID | Владелец (sub токена) |
| sessionId | UUID | Сессия подключения (sid из access-токена SSE); связь для per-session logout-очистки (002: logout отзывает одну сессию; edge «мультидевайс-logout») |
| expiresAt | epoch-ms | Горизонт жизни; продлевается heartbeat'ом (+90 c), research §G |
| createdAt | epoch-ms | Момент регистрации (диагностика) |

Правила:
- Валидация: connectionId валиден ⟺ найден в живых регистрациях ownerId (heartbeat чужого/истёкшего id → 404 `presence_connection_not_found`, research C3).
- Реконнект до истечения старой регистрации → новая запись с новым connectionId; дубль не искажает статус (edge: онлайн остаётся онлайн); осиротевшая истекает по score (FR-002).
- Истёкшая (score < now) регистрация исключается из расчёта статуса лениво (при чтении) и активно (watcher) — FR-002 самоистечение.

### 1.2 PresenceStatus (Присутствие — производное)

| Поле | Тип | Описание |
|---|---|---|
| userId | UUID | |
| online | boolean | ⟺ ≥1 живой регистрации (FR-001); мультидевайс — любая сессия |
| rev | int64 | Монотонная ревизия фактического/публикуемого состояния; инкремент на каждом переходе и переключении «невидимки»; основа сходимости клиентского слияния (research C2) |
| publishedStatus | `online` \| `offline` | Последний опубликованный аудитории статус (основа CAS-идемпотентности) |
| pendingOfflineAt | epoch-ms \| null | Запланированная публикация «офлайн» (гистерезис-очередь), FR-004 |

Переходы (state machine, публикация — только через атомарный CAS `publishedStatus`):

```text
[нет регистраций, published=offline]
   │ первая живая регистрация (SSE open / heartbeat revive)
   ▼ CAS offline→online, rev++, отмена offq ──► [published=online] ── публикация события аудитории (если не «невидимка»)
[published=online]
   │ потеря последней регистрации (SSE close / watcher-истечение)
   ▼ offq: pendingOfflineAt=now+45c (публикации НЕТ)
[pending offline]
   ├── восстановление ≥1 регистрации в окне → отмена (suppressed++), назад [online] без события
   └── окно истекло, регистраций 0 → CAS online→offline, rev++ ──► [published=offline] ── событие аудитории
[published=*]
   │ logout (REST 002, per-session) ──► очистка регистраций этой сессии (по sessionId);
   │   остались живые регистрации → статус не меняется; регистраций 0 → немедленный CAS→offline (обход offq)  [edge: без окна]
[published=online]
   │ включение «невидимки» ──► немедленный CAS→offline (rev++, одно переключение), заморозка событий
   │ выключение «невидимки» ──► публикация фактического статуса (rev++)
```

Инварианты:
- Наблюдаемое аудиторией значение = `publishedStatus` с учётом «невидимки» (`невидимка` ⇒ для окружения всегда `offline`, события заморожены) — FR-007.
- Серия разрывов < 45 c ⇒ 0 переключений; разрыв > окна ⇒ ровно одно (CAS исключает ≥2) — FR-004, SC-002.
- «офлайн» при тишине heartbeat гарантирован ≤ TTL(90c) + гистерезис(45c) + 2×poller-interval — SC-003.

### 1.3 PresenceEvent (Событие присутствия)

Кадр №18 `presence.updated`; payloads — contracts/presence-events.md §2. Не сохраняется нигде (FR-001: не история); адресуется только аудитории видимости; идемпотентно обрабатывается (rev-merge).

| Поле | Тип | Валидация |
|---|---|---|
| userId | UUID | субъект смены |
| status | `online` \| `offline` | опубликованное значение (для «невидимки» события не исходят) |
| rev | int64 | строго возрастает per-user; повторы/устаревшие — no-op на клиенте |

### 1.4 VisibilityAudience (Аудитория видимости)

Вычисляемое множество (не хранится; research C1):

```text
audience(X) = { активные участники чатов X (direct + group, state='active')   -- chat_participants V10/V14
                ∪ { владельцы контактов X }                                   -- user_contacts V11
              } − { блок-пары X в обе стороны } − { X }                       -- user_blocks V11
```

Инварианты: детерминирована текущим состоянием PG (добавление контакта/исключение из группы сходится без перезапуска — edge); событие/статус X получают только члены audience(X), иначе «нет доступа» (FR-003/FR-007, SC-004).

### 1.5 PresenceSettings (Настройка приватности)

| Поле | Тип | Валидация |
|---|---|---|
| userId | UUID | = users.id |
| incognito | boolean | persist между сессиями (FR-007); per-user, не per-device |

Хранение: PG `users.presence_hidden` (V15). Семантика переключения — §1.2; снапшот для «невидимки» всегда `offline` (неотличимость).

## 3. Структуры Redis (эфемерное состояние; TTL-семантика score'ами)

| Ключ | Тип | Содержимое | Жизненный цикл |
|---|---|---|---|
| `presence:alive:{userId}` | ZSET | member=connectionId, score=expiresAt | Ленивая чистка ZREMRANGEBYSCORE −inf..now при каждом чтении; удаление ключа при пустоте |
| `presence:watch` | ZSET (глобальный) | member=userId, score=max(expiresAt) регистраций | Триггер watcher'а тихих истечений; обновляется при каждом изменении регистраций |
| `presence:offq` | ZSET (глобальный) | member=userId, score=publishAt | Гистерезис-очередь; отменяется восстановлением, исполняется CAS-переходом |
| `presence:pub:{userId}` | String | `online` \| `offline` | Последний опубликованный статус; TTL 25 ч, продлевается heartbeat-ом и переходами; отсутствие ключа трактуется как `offline` (CAS nil→online валиден) |
| `presence:rev:{userId}` | String (int) | Монотонная ревизия | TTL 7 ч, продлевается при инкременте; при nil/истечении Lua инициализирует ревизию меткой now_ms (int64) — глобальная монотонность между «эпохами», клиентское правило «строго больше» сохраняется |
| `presence:online:count` | String (int) | Число опубликованных «онлайн» | Атомарно инкрементится/декрементируется в Lua-переходах; экспорт gauge FR-009 |

Атомарность: переходы (CAS pub + INCR rev + арифметика счётчика + offq-мутации) — Lua-скрипты; конкуренция поллеров/инстансов безопасна (повтор — no-op). Ключи перечисляемых множеств (watch/offq) батчево обрабатываются поллерами (LIMIT за тик) — O(log n) на операцию, без KEYS/SCAN (research A2).

## 4. Изменения OpenAPI (источник истины, аддитивно — 0.6.0 → 0.7.0)

- №36 `GET /users/me/presence?userIds=` — batch-снапшот (≤200) → `{items:[{userId,status,rev}]}`; `status: online|offline|unknown` (`unknown` = «нет доступа», семантика не различает «офлайн»/«скрыто»).
- №37 `POST /users/me/presence/heartbeat` `{connectionId}` → 204; 404 `presence_connection_not_found`.
- №38 `GET|PUT /users/me/presence/settings` `{incognito}`.
- №18: событие `presence.updated`; opening-фрейм `connected` `{connectionId}`.
- Коды проблем (RFC 9457): `presence_ids_too_many` (400), `presence_connection_not_found` (404), `flood_limit` (429, переиспользование).
