# Presence API Contract (007)

**Date**: 2026-10-01 | Источник истины: корневой `contracts/openapi.yaml` (0.6.0 → **0.7.0**, аддитивно) | Спека: [spec.md](../spec.md) FR-006–FR-008

Настоящий документ фиксирует решения plan-раунда; каноничные схемы/примеры — в openapi.yaml. Все операции — Bearer-only (конституция V), ошибки — RFC 9457 `application/problem+json` со snake_case кодами (конвенция 002).

## 1. №36 `GET /api/v1/users/me/presence` — снапшот отображаемых поверхностей

Batch-чтение статусов присутствия для открытых/отображаемых чатов и видимого списка «Контакты» (clarify 2026-10-01: только видимые поверхности, не вся аудитория).

- **Рабочая дефиниция «отображаемой поверхности»**: все смонтированные элементы списков «Чаты» и «Контакты» текущего экрана + открытый чат; попадание в вьюпорт не отслеживается. Серверу определение неизвестно — клиент просто передаёт `userIds` в batch ≤ 200; появление новой поверхности триггерит догрузку №36 только для недостающих (semantics owner — spec FR-003).

- **Query**: `userIds` — список UUID через запятую; ≤ 200 после дедупа.
- **Ответ 200**: `{ "items": [ { "userId": "uuid", "status": "online" | "offline" | "unknown", "rev": "int64" } ] }`
  - `online`/`offline` — последний опубликованный статус (`presence:pub`; единая гистерезисная семантика с `presence.updated` FR-004 — расхождения снимок/событие в окне pending-offline исключены — research C2);
  - `unknown` — единая семантика «нет доступа» (запрашивающий вне аудитории видимости или блок-пара); НЕ различает «офлайн» и «скрыто» (FR-007, US4 AC4);
  - цель в режиме «невидимки» отвечает `offline` — неотличимо от реального офлайна (FR-007, US4 AC2);
  - несуществующий userId — `unknown` (не раскрывает существование);
  - `rev` — ревизия статуса цели; клиент сливает с событиями по `max(rev)` (идемпотентность — FR-003, единый владелец семантики).
- **Ошибки**: 400 `presence_ids_too_many` (>200); 400 `malformed_request` (не-UUID в списке); 401 — общий Bearer-гейт.
- **Вызовы**: клиентский цикл (re)connect 005 (после sync/chats/contacts) и открытие новых поверхностей; лимит RPS — per-user бакет `flood_limit` (429 + Retry-After), консервативно, как №26.

## 2. №37 `POST /api/v1/users/me/presence/heartbeat` — продление регистрации

- **Тело**: `{ "connectionId": "uuid" }` — идентификатор из opening-фрейма `connected` канала №18 (presence-events.md §1).
- **Терминология**: presence-heartbeat №37 (прикладной: продлевает регистрацию, интервал 30 c) ≠ transport-keepalive SSE `:ka` канала №18 (кадр-комментарий каждые 15 с, 004 — удерживает TCP-соединение, к регистрации не относится); 404/429 на №37 не влияют на `:ka`, и наоборот.
- **Ответ**: 204 No Content; продлевает все горизонты регистрации до `now + 90 c` (Lua-атомарно: alive + watch, research A3).
- **Ошибки**: 404 `presence_connection_not_found` (id неизвестен или истёк; реакция клиента — немедленный reconnect SSE); 429 `flood_limit` (per-user бакет ~10 запросов/30 c — допуск на джиттер, реконнекты и мультидевайс до ~10 устройств при рекомендованном интервале heartbeat 30 c; сервер не требует точности). Реакция клиента на 429: сохранить SSE-соединение и повторить heartbeat в следующем интервале — TTL 90 c даёт 3× запас; немедленный reconnect — только на 404.
- **Параметры контракта** (FR-002, research §G): TTL регистрации **90 c**, интервал heartbeat **30 c** (3× запаса), гарантия обнаружения тишины ≤ TTL + гистерезис + 2×poller-interval (production ≈ 137 c) — SC-003, research §G.

## 3. №38 `GET|PUT /api/v1/users/me/presence/settings` — режим «невидимки»

Единый для standalone SPA и виджета; переключатель профиля/настроек (clarify 2026-10-01).

Соответствие имён: «невидимка» (spec.md/UI) ≡ поле `incognito` (№38) ≡ колонка `users.presence_hidden` (PG V15).

- **GET 200**: `{ "incognito": false }`
- **PUT** тело: `{ "incognito": true }` → 200 с сохранённым значением (идемпотентен; повтор той же величины — no-op без событий).
- **Семантика переключения** (research D1/D2): включение при живых подключениях публикует аудитории ровно одно переключение в `offline` и замораживает дальнейшие события; выключение публикует фактический статус (FR-007, US4 AC5). Действует на пользователя целиком, не на устройство; сохраняется между сессиями (PG V15).
- **Ошибки**: 400 `malformed_request` (не-boolean); 401; 429 `flood_limit` (PUT сверх per-user бакета, консервативно, как №26/№36).
