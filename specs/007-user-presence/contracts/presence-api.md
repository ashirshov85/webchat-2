# Presence API Contract (007)

**Date**: 2026-10-01 | Источник истины: корневой `contracts/openapi.yaml` (0.6.0 → **0.7.0**, аддитивно) | Спека: [spec.md](../spec.md) FR-006–FR-008

Настоящий документ фиксирует решения plan-раунда; каноничные схемы/примеры — в openapi.yaml. Все операции — Bearer-only (конституция V), ошибки — RFC 9457 `application/problem+json` со snake_case кодами (конвенция 002).

## 1. №36 `GET /api/v1/users/me/presence` — снапшот отображаемых поверхностей

Batch-чтение статусов присутствия для открытых/отображаемых чатов и видимого списка «Контакты» (clarify 2026-10-01: только видимые поверхности, не вся аудитория).

- **Query**: `userIds` — список UUID через запятую; ≤ 200 после дедупа.
- **Ответ 200**: `{ "items": [ { "userId": "uuid", "status": "online" | "offline" | "unknown", "rev": "int64" } ] }`
  - `online`/`offline` — последний опубликованный статус (`presence:pub`; единая гистерезисная семантика с `presence.updated` FR-004 — расхождения снимок/событие в окне pending-offline исключены — research C2);
  - `unknown` — единая семантика «нет доступа» (запрашивающий вне аудитории видимости или блок-пара); НЕ различает «офлайн» и «скрыто» (FR-007.4);
  - цель в режиме «невидимки» отвечает `offline` — неотличимо от реального офлайна (FR-007.2);
  - несуществующий userId — `unknown` (не раскрывает существование);
  - `rev` — ревизия статуса цели; клиент сливает с событиями по `max(rev)` (FR-006 идемпотентность).
- **Ошибки**: 400 `presence_ids_too_many` (>200); 400 `malformed_request` (не-UUID в списке); 401 — общий Bearer-гейт.
- **Вызовы**: клиентский цикл (re)connect 005 (после sync/chats/contacts) и открытие новых поверхностей; лимит RPS — per-user бакет `flood_limit` (429 + Retry-After), консервативно, как №26.

## 2. №37 `POST /api/v1/users/me/presence/heartbeat` — продление регистрации

- **Тело**: `{ "connectionId": "uuid" }` — идентификатор из opening-фрейма `connected` канала №18 (presence-events.md §1).
- **Ответ**: 204 No Content; продлевает все горизонты регистрации до `now + 90 c` (Lua-атомарно: alive + watch, research A3).
- **Ошибки**: 404 `presence_connection_not_found` (id неизвестен или истёк; реакция клиента — немедленный reconnect SSE); 429 `flood_limit` (интервал разумного использования — 30 c; контракт фиксирует рекомендацию, сервер не требует точности).
- **Параметры контракта** (FR-002, research §G): TTL регистрации **90 c**, интервал heartbeat **30 c** (3× запаса), гарантия обнаружения тишины ≤ 135 c (SC-003).

## 3. №38 `GET|PUT /api/v1/users/me/presence/settings` — режим «невидимки»

Единый для standalone SPA и виджета; переключатель профиля/настроек (clarify 2026-10-01).

- **GET 200**: `{ "incognito": false }`
- **PUT** тело: `{ "incognito": true }` → 200 с сохранённым значением (идемпотентен; повтор той же величины — no-op без событий).
- **Семантика переключения** (research D1/D2): включение при живых подключениях публикует аудитории ровно одно переключение в `offline` и замораживает дальнейшие события; выключение публикует фактический статус (FR-007.5). Действует на пользователя целиком, не на устройство; сохраняется между сессиями (PG V15).
- **Ошибки**: 400 `malformed_request` (не-boolean); 401.
