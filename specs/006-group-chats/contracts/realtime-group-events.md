# Contract: События группы на realtime-канале №18 (SSE)

**Feature**: 006-group-chats | **Источник истины**: `contracts/openapi.yaml` (операция №18 +
`components.schemas.Group*Event`)

События группы едут по тому же per-user потоку `GET /api/v1/users/me/events`, что и события 004
(фрейминг, аутентификация, retry/heartbeat — [realtime-channel.md 004
§1–§2](../../004-direct-messaging-core/contracts/realtime-channel.md) без изменений). Адресат —
активный участник группы на момент публикации: сервер берёт снимок активного состава в транзакции
операции и публикует post-commit в `rt:user:{userId}` каждого адресата. Решения и обоснование —
[research.md §4](../research.md), модель — [data-model.md §5](../data-model.md).

## 1. Доставка и «закрытие подписки»

- Канал — at-most-once (004): потерянный кадр не воспроизводится; сходимость — актуальное состояние
  по REST (№12/№28) и sync №26 при (пере)подключении. Офлайн-участник при подключении получает
  актуальные состав/роли/метаданные и пропущенные сообщения — но НЕ журнал событий (FR-015).
- **Идентификатор группы**: поле `groupId` всех событий группы равно `chatId` чата (id строки
  `chats`) — это единый ключ операций №12–№17/№26, операций групп №27–№35 и элементов списка «Чаты».
- События группы НЕ создают системных сообщений в истории (FR-015): история группы — только
  пользовательские сообщения (модель 004 без изменений).
- **Финальное событие и прекращение доставки**: при исключении/выходе адресату доставляется
  `group.you_removed` — последнее событие этой группы по его подписке; после коммита операции
  события группы в его канал больше не публикуются (состав читается из active-строк). Окно
  прекращения ≤ 5 с (FR-010/US5-3) — фактически равно латентности публикации. Поток пользователя
  физически НЕ закрывается: он мультиплексирует все чаты пользователя (004 §1); «закрытие
  подписки на группу» — логическое.
- **Гонка порядка**: сообщение, закоммиченное до исключения, может быть опубликовано после
  `group.you_removed` (post-commit публикации независимы). Клиент ОБЯЗАН после `group.you_removed`
  игнорировать последующие события этой группы и удалить её из списка «Чатов» — детерминированно,
  без поллинга (clarify 2026-09-25).
- **Идемпотентность**: повторный кадр (дубль доставки) применяется без искажений — обработчик
  применяет описанное состояние (роль/состав/метаданные), а не суммирует дельты (FR-015).
- Неизвестные `event:`-типы игнорируются (прямая совместимость, 004 §2).

## 2. Фрейминг (пример)

```text
event: group.member.added
data: {"groupId":"7dc5…","user":{"id":"9a2c…","username":"carol","email":"carol@example.com"},"actorId":"0f1e…"}

event: group.you_removed
data: {"groupId":"7dc5…","reason":"kicked"}
```

## 3. События

### 3.1 `group.updated` — метаданные изменены (FR-007)

Всем активным участникам. Клиент обновляет название в списке «Чатов» и заголовке без перезагрузки.

| Поле | Тип | Комментарий |
|---|---|---|
| `groupId` | uuid | группа |
| `title` | string | новое название |
| `description` | string \| null | новое описание |
| `actorId` | uuid | кто изменил (owner/admin) |

### 3.2 `group.member.added` — состав вырос (FR-002)

Всем активным участникам, включая добавленного(ых). Добавленному группа сразу видна в «Чатах»
(US1-2); его водяной знак инициализирован позицией группы (бейдж с 0, FR-013).

| Поле | Тип | Комментарий |
|---|---|---|
| `groupId` | uuid | группа |
| `user` | `PublicUser` | добавленный участник (роль — member) |
| `actorId` | uuid | кто добавил |

### 3.3 `group.member.removed` — состав уменьшился (исключение или выход)

Всем оставшимся активным участникам. Сам удалённый получает `group.you_removed` (§3.6).

| Поле | Тип | Комментарий |
|---|---|---|
| `groupId` | uuid | группа |
| `userId` | uuid | исключённый/вышедший |
| `actorId` | uuid \| null | кто исключил; `null` при самостоятельном выходе |

### 3.4 `group.role.changed` — роль изменена (FR-003)

Всем активным участникам. Передача владения = два кадра (новый owner; прежний → admin).

| Поле | Тип | Комментарий |
|---|---|---|
| `groupId` | uuid | группа |
| `userId` | uuid | чья роль |
| `role` | enum `owner\|admin\|member` | новая роль |
| `actorId` | uuid | кто изменил (owner) |

### 3.5 `group.deleted` — группа удалена владельцем (FR-006)

Всем бывшим активным участникам (снимок состава до удаления). Клиент убирает группу из списка
«Чатов» и закрывает окна; повторные события группы игнорируются.

| Поле | Тип | Комментарий |
|---|---|---|
| `groupId` | uuid | группа |
| `actorId` | uuid | владелец, выполнивший удаление |

### 3.6 `group.you_removed` — финальное событие для исключённого/вышедшего (FR-010/FR-015)

Адресуется ТОЛЬКО затронутому пользователю (все его устройства/сессии); последнее событие группы
по его подписке.

| Поле | Тип | Комментарий |
|---|---|---|
| `groupId` | uuid | группа |
| `reason` | enum `kicked\|left` | исключён владельцем/админом или вышел самостоятельно |

### 3.7 `message.created` / `chat.read` в группах (004, расширение адресатов)

- `message.created`: всем активным участникам, КРОМЕ отправителя (FR-011); payload — схема 004
  без изменений (`chatId` = id группы); клиент дедуплицирует по `message.id`.
- `chat.read`: всем активным участникам, кроме читавшего; payload 004 без изменений
  (`chatId, readUpToSeq, byUserId`). ✓✓ отправителя: собственное сообщение прочитано всеми ⟺
  `seq ≤ MIN(last_read_seq)` активных участников, кроме отправителя (проекция
  `othersReadUpToSeq`, №13/№26); статус монотонен — клиент держит max и не отрисовывает откат
  (исключённые из условия выпадают натурально, FR-012).

## 4. Отражение в openapi.yaml

- `components.schemas.Group*Event` — payloads §3 (имена полей совпадают).
- `paths./api/v1/users/me/events.get`: описание потока дополняется перечнем событий группы и
  семантикой §1 (финальность `group.you_removed`, идемпотентность, игнорирование неизвестных
  типов).
- Изменение состава событий/полей — только additive (конституция IV; BREAKING.md не требуется).

## 5. Клиентские правила (нормативно для контракта)

1. Обработка идемпотентна: состояние (состав/роли/метаданные), не дельты (FR-015).
2. После `group.you_removed` / `group.deleted` — группа удаляется из «Чатов»; события этой группы
   игнорируются (гонка порядка §1).
3. Статусы ✓✓ — по `othersReadUpToSeq` (№13/№26) и `chat.read`-кадрам; монотонно (max).
4. Офлайн-период восполняется REST/sync (актуальное состояние), не журналом событий (FR-015).
5. После `group.you_removed`/`group.deleted` группа исключается и из отложенных ack-батчей №25
   (иначе весь батч получит `403 not_participant` — all-or-refusal 005).
