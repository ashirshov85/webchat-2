# Quickstart: Видеоконференции в чатах (речь, видео, демонстрация экрана)

**Feature**: 009-video-conferences | **Date**: 2026-10-15

Руководство по end-to-end проверке фичи вручную и автотестами. Детали: [операции API](./contracts/api-contract.md),
[события SSE](./contracts/realtime-conference-events.md), [интеграция LiveKit](./contracts/livekit-integration.md),
[модель данных](./data-model.md), [решения](./research.md). База — сценарии 002/004/006
([quickstart 004](../../004-direct-messaging-core/quickstart.md), [quickstart 006](../../006-group-chats/quickstart.md));
здесь проверяются конференции, pre-join, модерация, гости и жизненный цикл. Все проверки —
настольные браузеры (Chrome/Firefox/Safari/Edge — Q8=A).

## 1. Предпосылки

- JDK 21, Node 24 + pnpm, Docker (Testcontainers и локальная инфраструктура).
- Клон репозитория, ветка `009-video-conferences`.
- Аккаунты 002: `alice`, `bob`, `carol` (+ «дейв без аккаунта» — браузер в приватном режиме
  для гостя). Групповой чат alice→bob,carol и личный alice↔bob (см. quickstart 004/006).

## 2. Локальная инфраструктура и запуск

```bash
docker compose -f deploy/local/docker-compose.yml up -d postgres redis mailpit livekit
./gradlew bootRun                                          # workdir backend/ — Flyway применяет V18
pnpm --dir frontend dev                                    # SPA :5173, /api → :8080
```

- Обязательные env backend — как в 005 (`AUTH_IP_HASH_PEPPER`, `AUTH_JWT_KEYS`,
  `AUTH_JWT_ACTIVE_KID`) — см. [quickstart 005 §2](../../005-delivery-resilience/quickstart.md).
- Новые env: `LIVEKIT_URL=http://localhost:7880`, `LIVEKIT_API_KEY=devkey`,
  `LIVEKIT_API_SECRET=secret` (сервис `livekit` в compose поднимает сервер с webhook на бэкенд
  и `enable_remote_unmute`, [livekit-integration.md §1](./contracts/livekit-integration.md)).
- Настройки фичи (`conferences.*`) — дефолты Q19 в `application.yml`: maxParticipants, TTL
  ссылки 24 ч, пустая комната 60 с, длительность 4 ч, имя гостя ≤ 50. Для быстрых проверок
  таймаутов — заниженные значения, например
  `SPRING_APPLICATION_JSON='{"conferences":{"empty-room-timeout-seconds":10,"max-duration":"PT2M","warning-before-end":"PT30S","max-participants":3}}'`.

Далее: 2–3 браузера/приватных окна; HTTP — с `Authorization: Bearer <accessToken>`;
SSE — DevTools → Network → EventStream. Камера/микрофон — реальные или
`getUserMedia`-флаги Chrome (`--use-fake-device-for-media-stream`,
`--use-fake-ui-for-media-stream` — удобно для e2e).

## 3. Сценарии проверки

### 3.1 Создание звонка из чата и подключение (US1) — SC-001/SC-002

1. alice: в личном чате с bob нажимает «видеозвонок» в заголовке → появляется системная
   карточка-приглашение с кнопкой «Подключиться»; `201` от №44; повторное нажатие — та же
   конференция (`200`), карточка не дублируется.
2. bob: видит карточку в истории → «Подключиться» → pre-join → «Войти» → оба в конференции,
   видят и слышат друг друга; время от «Войти» до медиа ≤ 5 с (SC-001).
3. Приватность (SC-002): carol (не член личного чата) открывает ссылку `/conference/{id}` →
   `403 conference_forbidden` на №47, токен не выдаётся.
4. Демонстрация экрана каждым участником видна другим; при деградации сети (DevTools throttle)
   качество понижается без обрыва (simulcast).
5. Аудиозвонок: создатель входит с микрофоном без камеры; камера включается в звонке (soft).
6. Групповой чат: тот же флоу с 3 участниками.
7. Все вышли → через таймаут пустой комнаты (индикатор в LiveKit уходит, `room_finished`)
   → SSE `conference.ended`; старая ссылка показывает «конференция завершена» (№45/№47 → 409).

### 3.2 Pre-join экран (US2) — FR-005–FR-007

1. Из каждой точки входа (видеозвонок / аудиозвонок / ссылка-приглашение / гостевая ссылка) —
   один и тот же pre-join: превью, тумблеры, выбор устройств, «Войти».
2. Дефолты: видеозвонок → камера+микрофон; аудиозвонок/ссылки → только микрофон, тумблер
   камеры доступен (soft).
3. Оба тумблера выключены → вход «только слушаю», публикация включается тумблерами в звонке.
4. Запрет доступа браузером к устройствам → предупреждение, вход доступен; повторный запрос
   разрешения — в звонке (Q6=A).
5. Открытый pre-join не занимает слот (участник не отображается у других), закрытый без
   «Войти» не оставляет следов.
6. При «праве слова» у участника (см. 3.3) тумблеры на pre-join заблокированы с пояснением
   (данные №46).

### 3.3 Модерация (US3) — SC-005

1. alice (создатель = модератор) открывает панель участников: глушит bob'у микрофон → у bob
   тумблер заблокирован, у всех состояние видно; ≤ 2 с (SC-005).
2. Отключение камеры; отключение демонстрации экрана (точечно, Q22=A).
3. «Право слова»: все публикации bob заблокированы (аудио/видео/экран, Q4=A), тумблеры
   заблокированы с пояснением.
4. Назначение carol модератором; carol применяет действия к bob и к alice (равноправие, Q21=A);
   снятие роли.
5. Персистентность (Q5/Q9=A): bob с ограничением выходит и переподключается → ограничение
   действует; alice выходит — сохраняет роль модератора по возвращении.
6. Кик bob'а → мгновенное отключение; bob переподлачивается по ссылке из чата — допустимо.
7. Завершение конференции модератором → все отключены, SSE `conference.ended`, история чата
   не изменилась (Q20=A).

### 3.4 Гостевой доступ (US4) — SC-003/SC-004

1. alice генерирует гостевую ссылку (№52) → в чат не постится; ссылка копируется.
2. Приватное окно без аккаунта: открытие ссылки → invite-info валиден → ввод имени → pre-join
   (только микрофон) → «Войти» → в конференции с пометкой «гость» (≤ 3 действий, SC-003).
3. Гость не имеет доступа к чату (API чатов без Bearer недоступны; на странице — только звонок).
4. Гость включает камеру/экран тумблерами в звонке (Q1=C); модератор глушит/кикает гостя.
5. Отзыв ссылки (№53) → все вошедшие по ней гости отключаются немедленно, новые входы — отказ
   (Q13=B); генерация новой отзывает предыдущую (Q17=A).
6. Негативные: истёкший TTL (`conferences.guest-invite-ttl` занизить), подделанный nonce
   (`inviteToken=garbage`), пустое/пробельное/51-символьное имя → понятные отказы (SC-003).
7. Rate limiting (SC-004): серия №54/№55 сверх лимита → `429` problem+json; прочие API
   (№12/№27 и др.) не деградируют (Δp99 ≤ 10 % по метрикам).
8. Квота: `max-participants=3` → четвёртое подключение — `409 conference_full` (гости и члены
   делят квоту, Q23=A); два подключения одной вкладкой — второе покидает первую (Q10=A).
9. Член чата по гостевой ссылке входит как гость (Q14=A); его вход через «Подключиться» —
   как участник.

### 3.5 События и жизненный цикл (US5) — SC-006/SC-007

1. carol, не входя в звонок, получает по SSE `conference.started` (индикатор «звонок идёт»)
   и `conference.ended` — ≤ 2 с (SC-006).
2. Пустая комната: все вышли → комната закрыта LiveKit не позднее таймаута; повторное
   подключение по старым токенам невозможно (SC-007).
3. Потеря вебхука: остановить контейнер livekit на >grace, запустить → sweeper завершает
   «зависшую» конференцию (SC-007); недоступность медиа в середине звонка: остановка/старт
   livekit → индикация, переподключение или контролируемое завершение (Q15=B).
4. Максимум длительности (заниженный `max-duration`): предупреждение участникам (SSE +
   data-топик — видно гостю), затем контролируемое завершение (Q16=B).
5. Исключение bob из группы во время звонка → его подключение разрывается, повторный join
   запрещён (FR-003 edge).

## 4. Автотесты и команды

```bash
# backend: IT с Testcontainers (PG+Redis+LiveKit) и unit
./gradlew test --tests 'webchat.backend.conferences.*'      # workdir backend/
# фронтенд: unit (pre-join дефолты/блокировки, join-страница, карточка, SSE-индикатор)
pnpm --dir frontend test src/conferences
# e2e звонка двух вкладок против локального LiveKit (fake media)
pnpm --dir frontend exec playwright test tests/e2e/conferences.spec.ts
# контракт: vacuum → генерация TS → drift → oasdiff (без breaking)
./scripts/validate-contracts.sh
# нагрузочный smoke контрольной плоскости (создание/join/гость/лимиты)
docker run --rm -i grafana/k6 run - < load/k6/conferences.smoke.js
```

Медиа-нагрузка (SC-008): прогон `lk load-test` против dev-стенда по требованиям
к окружениям ROADMAP (VPS 4 vCPU / 6 ГБ, limits cpu ~1500m–2 / mem 1–1.5Gi, 720p,
maxParticipants ≤ 16; ёмкость стенда ~10 одновременных 1:1 / ~2 групповых)
с экстраполяцией по формуле [research.md §12](./research.md);
полный прогон — фича 016. Метрики `webchat_conference_*` (FR-018) — Actuator
`/actuator/prometheus`; по ним проверяются SC-001–SC-009.

## 5. Критерии готовности ручной проверки

- US1–US5 прогоняются целиком на local-compose с реальными камерами/микрофонами двух машин
  (или fake-устройств), включая негативные ветки 3.1.3, 3.4.5–3.4.8, 3.5.2–3.5.5.
- Ни один шаг не требует доступа гостя к чату; ни один отказ не раскрывает деталей конференции.
