# Contract: Realtime-события конференций (SSE-канал №18)

**Feature**: 009-video-conferences | **Источник истины**: `contracts/openapi.yaml` (async
канал `/api/v1/users/me/events`)

Два новых `event:`-типа существующего per-user SSE-канала (`rt:user:{userId}`, публикация
post-commit через `RealtimeEventPublisher` — конвенция 004/006/007). События адресованы
**активным членам чата** (снимок членства в транзакции перехода статуса), доставляются в
реальном времени, ≤ 2 с в 95 % случаев (SC-006), at-least-once (консьюмер идемпотентен —
см. семантику). Оповещение о звонке — только in-app (индикатор «звонок идёт» + voluntary-вход
по кнопке; рингтон/accept-decline вне v1, Q12=A). События конференции **не являются**
пользовательскими сообщениями и в историю чата не пишутся (FR-013, Q20=A).

## 1. `conference.started`

```json
event: conference.started
data: {"conferenceId":"<uuid>","chatId":"<uuid>","startedAt":"<iso8601>","mode":"video|audio"}
```

- **Когда**: первый участник фактически вошёл (вебхук `room_started` → переход
  `created → active`; research §7). Ровно один раз на конференцию: повторные/дублированные
  вебхуки не порождают повторных событий (условный переход статуса).
- **Получатели**: активные члены чата на момент входа первого участника (не только участники
  звонка — US5-1: член чата видит «звонок идёт», даже не открывая его).
- **Действие клиента**: бейдж/индикатор активного звонка у чата (список чатов + заголовок),
  активная кнопка входа.

## 2. `conference.ended`

```json
event: conference.ended
data: {"conferenceId":"<uuid>","chatId":"<uuid>","endedAt":"<iso8601>","reason":"last_left|moderator|max_duration|room_lost|chat_deleted"}
```

- **Когда**: любой путь завершения (последний вышел + таймаут пустой комнаты / модератор /
  максимум длительности / потеря медиа-комнаты / удаление чата) — единый идемпотентный
  `finalize` (research §7). Ровно один раз на конференцию.
- **Получатели**: активные члены чата на момент завершения.
- **Действие клиента**: снять индикатор; если участник в звонке — клиент закрывается по
  Disconnected от LiveKit (событие дублирует причину для UX-сообщения).
- **История чата не изменяется** (Q20=A): след завершения — только это событие и ответ
  «конференция завершена» по старой ссылке (№45 `status='ended'`).

## 3. Сопутствующие изменения существующих событий

- `message.created` (№19, без изменений формата доставки): payload расширен полями `kind`
  (`"user"|"system"`) и `payload` (объект виджета, для системных обязательно) + `senderId`
  теперь nullable. Клиент v1 рендерит `payload.type="conference_invite"` карточкой с кнопкой
  «Подключиться»; неизвестные `payload.type` — нейтральный плейсхолдер (OCP).

## 4. Гарантии и семантика доставки

| Свойство | Значение |
|---|---|
| Канал | существующий `rt:user:{userId}` (SSE №18), мультиплексирован с остальными событиями |
| Публикация | строго post-commit (TransactionSynchronization), как 004/006 |
| Доставка | at-least-once; дубли безопасны: клиент применяет событие как функцию статуса (`звонок идёт / не идёт`), а не накапливает |
| Порядок | per-user канал сохраняет порядок публикации; `started` публикуется раньше `ended` одной конференции (жизненный цикл в одном статусном поле) |
| Полнота | потеря события компенсируется REST: №45 `GET ConferenceView.status` — источник для индикатора при переподключении SSE |
| Адресация | гостям события **не доставляются** (нет userId/SSE) — их канал оповещений: data-пакеты LiveKit (`conference.warning`, research §7) и Disconnected комнаты |
