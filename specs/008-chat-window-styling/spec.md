# Feature Specification: Стилизация окна чата по дизайн-макету «Aethergram»

**Feature Branch**: `008-chat-window-styling`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: "Действующий мессенджер (наследие фич 004–007: личные чаты, группы с ролями, presence, outbox/синхронизация, контакты) приводится к утверждённому статическому прототипу tmp/chats.html («Aethergram»: стимпанк-палитра auth-экрана, шрифты Old Standard TT / Cormorant SC / Anonymous Pro, корпус-«машина» с окантовкой и заклёпками, фоновые паттерны, зерно/виньетка). Точное соответствие типографике, сетке, отступам и палитре для всех поверхностей: сайдбар (поиск, список чатов с аватарами, бейджами «99+», меткой «заблокирован», временем последнего сообщения) и окно чата (заголовок с аватаром, статусом и кнопками, лента с пузырями и штампами ✓/✓✓, композер). Табы «Чаты»/«Контакты» сайдбара убираются: главное меню кнопкой у поиска (Мой профиль / Контакты / Создать групповой чат), контакты — модальное окно (поиск, добавление точным совпадением, сортировка, блокировка, удаление чата/контакта), «Мой профиль» — модальная форма (username/email readonly + инкогнито, API 007). Поверх рескина добавляется UI-слой без изменения API: аватары с инициалами (из username, октагональные у групп) и presence-точкой, время сообщений и разделители дат (createdAt уже в контрактах), тосты, модальные окна и контекстные меню, мобильный burger-drawer, звуковые оповещения отправки/приёма (WebAudio, без персистентной настройки), состояние «заблокирован» в композере. Сохраняются и стилизуются все функции 005–007: статусы outbox («не отправлено», повтор/удаление, переполнение очереди, отсчёт ретрая флуд-лимита), индикатор синхронизации, пагинация истории, роли групп и ростер-действия, описание группы, presence «неизвестно», страницы настроек. Контракты API и доменная логика не меняются. Typing-индикатор, lastSeen, отображаемые имена и переключатель звука per-chat — фича 008a; поиск по сообщениям — 013."

## Clarifications

### Session 2026-10-03

- Q: Какой уровень доступности (a11y) должен обеспечить новый интерфейс фичи 008? → A: Полная клавиатурная навигация и управление фокусом (меню, модальные окна, drawer, списки); WCAG-контраст, ARIA и скринридеры в объём фичи не входят.
- Q: Какие браузеры и устройства обязаны поддерживаться новым UI как минимальная матрица? → A: Последние 2 версии Chrome, Edge, Firefox, Safari — desktop и мобильные.
- Q: Какие измеримые бюджеты производительности UI зафиксировать для ленты сообщений и анимаций? → A: 60 fps анимаций и прокрутки; первый рендер экрана чата ≤ 1 с; плавность ленты при 1000+ сообщений.
- Q: Как определяется «согласованный допуск» визуального сравнения с эталонными снимками в SC-001? → A: Числовой порог — не более ~2% отличающихся пикселей на ключевой экран.
- Q: Где должен храниться нормативный прототип `tmp/chats.html`, на который ссылаются FR-001 и SC-001? → A: Версионированная копия в `specs/008-chat-window-styling/design/chats.html`; ссылки спеки обновлены на этот путь.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Рескин «машины Aethergram»: сайдбар и окно чата в точном соответствии прототипу (Priority: P1)

Пользователь открывает мессенджер и видит «машину» из утверждённого прототипа: корпус с золотой окантовкой и заклёпками на панелях, тёмные фоновые паттерны (шестерёнки — общий фон, орнамент — лента сообщений), зерно и виньетка поверх всего. Типографика по прототипу: Old Standard TT (основной текст, курсивные подписи), Cormorant SC (заголовки, имена, бейджи, кнопки-надписи), Anonymous Pro (поля ввода, текст сообщений, моноширинные значения); все три шрифта покрывают кириллицу и латиницу. Сайдбар (поиск, список чатов с аватарами, бейджами «99+», меткой «заблокирован», временем последнего сообщения и превью) и окно чата (заголовок с аватаром, статусом и кнопками; лента с пузырями — исходящие «золотая пластина», входящие «тёмная панель» — и штампами ✓/✓✓; композер в золотой раме) в точности соответствуют прототипу по типографике, сетке, отступам и палитре. Вся функциональность фич 004–007 сохраняется без изменений поведения.

**Why this priority**: Это минимальный жизнеспособный продукт фичи — сам утверждённый визуальный облик основных поверхностей с сохранением работоспособности мессенджера; всё остальное (новая навигация, UI-слой, состояния) наслаивается на этот каркас.

**Independent Test**: Проверяется сравнением ключевых экранов с эталонными снимками, произведёнными по прототипу (визуальная регрессия), и прогоном существующих приёмочных сценариев отправки/чтения сообщений: облик соответствует прототипу, все операции работают.

**Acceptance Scenarios**:

1. **Given** мессенджер открыт на любом экране (список чатов, личный чат, группа), **When** интерфейс отображается, **Then** корпус, панели, окантовка, заклёпки, фоновые паттерны, зерно и виньетка соответствуют эталонным снимкам по прототипу в рамках согласованного допуска сравнения.
2. **Given** переписка с исходящими сообщениями в состояниях «доставлено» и «прочитано», **When** лента отображается, **Then** исходящие пузыри — «золотая пластина», входящие — «тёмная панель» с радиусами по прототипу; у исходящих — штампы ✓ (доставлено) и ✓✓ (прочитано) в «гравированном» стиле с анимацией штамповки при смене статуса.
3. **Given** несколько чатов с непрочитанными, один — 100 и более, **When** список чатов отображается, **Then** у каждого чата с непрочитанными — бейдж с числом, при 100 и более — «99+».
4. **Given** поле ввода в фокусе, **When** пользователь отправляет сообщение кнопкой «ОТПРАВИТЬ» или Enter, **Then** сообщение появляется в ленте с анимацией по прототипу, фокус остаётся в поле ввода (кнопка отправки не забирает фокус).
5. **Given** системная настройка «уменьшить движение» включена, **When** интерфейс рендерится, **Then** анимации (мерцание ламп, появление пузырей, штамп, «пар») отключены, статичные паттерны и текстуры сохранены.

### User Story 2 - Навигация без табов: главное меню, модальные «Контакты» и «Мой профиль» (Priority: P1)

Табы «Чаты»/«Контакты» сайдбара убраны. Рядом с поиском — кнопка главного меню с пунктами «Мой профиль», «Контакты», «Создать групповой чат». «Контакты» — модальное окно: список контактов с сортировкой по имени, затем по username; поиск по имени/username/email; добавление контакта точным совпадением username или email (без учёта регистра); контекстное меню контакта «⋯» с действиями: заблокировать/разблокировать (с подтверждением), удалить чат (контакт сохраняется) или создать чат (если удалён), удалить контакт (чат и история сохраняются); пометки «заблокирован» и «чат удалён» в списке. «Мой профиль» — модальная форма: username и email только для чтения, переключатель «Режим инкогнито» (API 007), сохранение с уведомлением. Заблокированный контакт: метка в списке чатов, композер неактивен с подсказкой, отправка невозможна.

**Why this priority**: Табы удаляются — без нового пути к контактам, профилю и созданию групп мессенджер теряет доступ к функциям 004–007; это обязательное продолжение US1 в одном релизе, самостоятельно тестируемое через достижимость всех операций.

**Independent Test**: Проверяется сценарно: все операции 004–007 (добавление/удаление контакта, блокировка/разблокировка, удаление/создание чата, инкогнито, создание группы) выполняются только через главное меню и модальные окна, без табов, и завершаются успешно.

**Acceptance Scenarios**:

1. **Given** список чатов открыт, **When** нажата кнопка главного меню у поиска, **Then** открывается меню с пунктами «Мой профиль», «Контакты», «Создать групповой чат»; повторный клик или клик вне — закрывает.
2. **Given** открыто модальное окно «Контакты», **When** в поле поиска вводится подстрока, **Then** список фильтруется по имени, username или email без учёта регистра; пустой результат — «Ничего не найдено», отсутствие контактов — «Нет контактов».
3. **Given** форма добавления контакта, **When** введено точное совпадение username или email (без учёта регистра), **Then** контакт добавляется, открывается переписка, показывается тост; **When** совпадения нет, **Then** выводится ошибка «требуется точное совпадение», контакт не создаётся; **When** пользователь уже в контактах, **Then** операция идемпотентна: открывается переписка, тост «Уже в контактах».
4. **Given** контакт с чатом, **When** выполнено «Удалить чат» (с подтверждением), **Then** чат удалён из списка, контакт сохранён, у контакта появляется пометка «чат удалён»; **When** выполнено «Удалить контакт» (с подтверждением), **Then** контакт удалён, чат и история сохранены и живут на данных собеседника.
5. **Given** открыт чат с заблокированным контактом, **When** пользователь пытается писать, **Then** поле и кнопка отправки неактивны, показана подсказка о блокировке; **When** контакт разблокирован (с подтверждением), **Then** композер снова активен.
6. **Given** форма «Мой профиль», **When** пользователь включает «Режим инкогнито» и сохраняет, **Then** для окружающих он отображается «офлайн» (семантика 007), username и email недоступны для редактирования, показывается тост с подтверждением.

### User Story 3 - UI-слой без изменения API: аватары, время, разделители дат, тосты, контекстные меню и подтверждения (Priority: P2)

Поверх рескина добавляется UI-слой на основе уже существующих данных (без изменения API): аватары с инициалами из username (две буквы; октагональная форма у групповых чатов, детерминированный цвет из палитры прототипа) и presence-точкой на аватарах личных чатов и контактов (зелёная с мягким свечением — «онлайн», тусклая — «офлайн», нейтральная — «неизвестно» по 007); время каждого сообщения (из createdAt) и разделители дат между днями; тосты для результатов операций; контекстные меню (главное, контактное «⋯», меню чата «шестерёнка») с корректным позиционированием; модальные подтверждения для деструктивных действий. В групповом заголовке при наведении на статус — всплывающий список участников («Вы» первым, пометка «администратор»).

**Why this priority**: Обогащение поверхностей деталями утверждённого облика без которых соответствие прототипу неполно; при этом базовый обмен сообщениями (US1) и достижимость функций (US2) уже обеспечены, поэтому P2.

**Independent Test**: Проверяется визуальным сравнением и сценарно: аватары/время/разделители отображаются по прототипу на существующих данных; каждая операция из US2 завершается ровно одним тостом; меню открываются, позиционируются в пределах экрана и закрываются по клику вне/Esc.

**Acceptance Scenarios**:

1. **Given** чаты (личные и группы) и контакты, **When** отображаются списки, **Then** у каждого элемента — аватар с инициалами из username (две буквы), у групп — октагональный, цвет детерминирован одним и тем же значением для одного пользователя.
2. **Given** собеседник в состояниях «онлайн», «офлайн», «неизвестно» (007), **When** avatar и статус заголовка рендерятся, **Then** presence-точка и лампа статуса соответствуют состоянию (зелёная мерцающая / тусклая / нейтральная), текст статуса — «В сети» либо нейтральное состояние «неизвестно» (без ложного «офлайн»).
3. **Given** сообщения, отправленные в разные дни, **When** лента отображается, **Then** между днями — разделители дат в длинном формате по прототипу; у каждого сообщения — время в формате ЧЧ:ММ из createdAt.
4. **Given** завершается операция (добавление контакта, блокировка, разблокировка, удаление, создание группы, сохранение профиля), **When** операция успешна или отклонена, **Then** показывается ровно один тост с результатом, авто-скрытие через ~3 секунды.
5. **Given** открыто контекстное меню или всплывающий список участников у края экрана, **When** меню отображается, **Then** оно смещается, чтобы полностью помещаться в экран; клик вне или Esc закрывает; деструктивные пункты визуально выделены.

### User Story 4 - Стилизованные состояния доставки и устойчивости 005–007 (Priority: P2)

Все функции фич 005–007 сохраняются и оформляются в дизайн-систему прототипа: статусы outbox («отправляется», «не отправлено» с действиями повторить/удалить, баннер переполнения очереди, отсчёт ретрая флуд-лимита в композере), индикатор синхронизации при разрывах и восстановлении, пагинация истории при прокрутке вверх (разделители дат корректны на стыках страниц), роли групп и ростер-действия из меню «шестерёнки» (участники, редактирование названия и описания группы, добавление/удаление участников для владельца/администратора; выход из чата для участника; добавление собеседника в контакты, если его там нет), presence «неизвестно» на всех поверхностях, существующие страницы настроек — переоформлены без потери функций; пустые, загрузочные и ошибочные состояния окна чата оформлены в едином стиле.

**Why this priority**: Гарантия, что рескин не сузил функциональность и все состояния устойчивости видимы и понятны в новом облике; самостоятельно тестируемо прогоном сценариев 005–007 на новом UI.

**Independent Test**: Проверяется прогоном существующих приёмочных сценариев фич 005–007 (сбой отправки, переполнение очереди, флуд-лимит, разрыв связи, длинная история, управление группой, настройки): каждый сценарий завершается успешно, все состояния отображаются в дизайн-системе прототипа.

**Acceptance Scenarios**:

1. **Given** отправка сообщения завершилась сбоем, **When** сообщение отображается в ленте, **Then** оно помечено «не отправлено» в стиле дизайн-системы, доступны действия «повторить» и «удалить»; повтор сохраняет идемпотентность (без дублей).
2. **Given** очередь отправки переполнена или действует флуд-лимит, **When** композер отображается, **Then** показывается баннер переполнения и/или отсчёт времени до доступной отправки; ввод может быть заблокирован до истечения отсчёта (существующая логика), оформление — по дизайн-системе.
3. **Given** соединение разорвано и восстановлено, **When** клиент синхронизируется, **Then** индикатор синхронизации отображается в стиле дизайн-системы; пропущенные сообщения доставляются без дублей и пропусков (семантика 005).
4. **Given** история длиннее одной страницы, **When** пользователь прокручивает ленту вверх, **Then** подгружаются более старые сообщения (пагинация), на стыке страниц разделители дат и порядок сообщений корректны.
5. **Given** пользователь — владелец/администратор группы, **When** открыто меню «шестерёнки», **Then** доступны участники, редактирование (название, описание, состав участников) и удаление чата; **Given** обычный участник, **Then** доступны участники и выход из чата; собеседник личного чата вне контактов добавляется в контакты из меню чата.

### User Story 5 - Мобильный burger-drawer и звуковые оповещения (Priority: P3)

На узких экранах (до ~900px) сайдбар превращается в выдвижной drawer: слева — плавающая burger-кнопка, открытие — с затемнением фона, выбор чата автоматически закрывает drawer. На широких экранах «машина» целиком вписывается в окно без прокрутки страницы. Звуковые оповещения отправки и приёма — короткие синтезируемые сигналы в «телеграфной» стилистике (отправка — щелчок телеграфа, приём — латунный звоночек), без настройки и персистентного состояния; при запрете автозвука до первого действия пользователя звук пропускается без ошибок, визуальные уведомления работают независимо.

**Why this priority**: Адаптивность и звук — завершающие штрихи облика из прототипа; обмен сообщениями и все функции доступны и без них, поэтому P3.

**Independent Test**: Проверяется на узком экране: burger открывает/закрывает drawer, выбор чата закрывает; на широком — прокрутки страницы нет; при отправке и приёме сообщений звучат сигналы, при блокировке автозвука функциональность не нарушается.

**Acceptance Scenarios**:

1. **Given** экран шириной до ~900px, **When** нажата burger-кнопка, **Then** сайдбар выдвигается поверх контента с затемнением; повторное нажатие, клик по затемнению или выбор чата — закрывает.
2. **Given** экран шириной более ~900px, **When** мессенджер открыт, **Then** «машина» целиком вписывается в окно, прокрутки страницы нет, burger-кнопка скрыта.
3. **Given** звук не отключён (настройки нет — всегда включён), **When** пользователь отправляет сообщение, **When** в открытый чат приходит входящее, **Then** звучат различные короткие сигналы (отправка — щелчок, приём — звоночек) один раз на событие.
4. **Given** браузер запрещает звук до первого действия пользователя, **When** событие звука происходит раньше, **Then** звук пропускается молча, ошибки и поломки отправки/приёма исключены.
5. **Given** очень узкий экран (до ~480px), **When** композер и пузыри отображаются, **Then** кнопка отправки компактна, пузырь занимает до ~84% ширины ленты, ввод остаётся удобным.

### Edge Cases

- Длинные имена чатов/контактов и превью последних сообщений — усечение с многоточием, без разрушения сетки; полный текст доступен во всплывающей подсказке.
- Непрочитанных 100 и больше — бейдж показывает «99+», точное число не обязано помещаться.
- Заблокированный контакт: метка в списке чатов и в списке контактов, композер неактивен с подсказкой; разблокировка (с подтверждением) возвращает активность — поведение блокировки 004 не меняется.
- Сообщения в пределах одного дня — разделитель дат один; лента через полночь — появляется новый разделитель; на стыке страниц пагинации разделитель вставляется ровно один раз.
- Пустые состояния: нет чатов, нет контактов, нет сообщений в чате («Нет сообщений»), пустой результат поиска («Ничего не найдено»), все контакты уже в группе — оформлены в едином стиле.
- Отсутствие или задержка снимка присутствия (вход, переподключение) — индикатор нейтрален («неизвестно»), ложный «офлайн» до получения данных не отображается (семантика 007).
- prefers-reduced-motion: все анимации (мерцание ламп, появление пузырей, штамп, «пар»,drawer) отключаются; интерфейс остаётся полностью читаемым.
- Контекстное меню или всплывающий список участников у края экрана — смещается в пределы экрана, не обрезается.
- Стекирование слоёв: тост поверх модального окна; Esc закрывает слои сверху вниз (контекстное меню → модальное окно → drawer).
- Подтверждение поверх открытой модальной формы (например, добавление контакта → подтверждение) — модальная оболочка переключает форму без наложения фонов.
- Смешанный текст кириллицей и латиницей — единообразная типографика (все три шрифта покрывают оба алфавита), «тофу» и подмена шрифта внутри блока недопустимы.
- Очень длинное слово без пробелов — перенос по символам, пузырь не ломает сетку ленты.
- Шрифты не загрузились (нет сети) — резервные стеки читаемы, структура layout не разрушается.
- Два пользователя с одинаковыми инициалами или цветом аватара — допустимо; различие обеспечивается именем.
- Отправка кнопкой не смещает фокус из поля ввода (кнопка не «забирает» фокус на нажатии).
- Анимация срабатывания штампа ✓/✓✓ при массовом обновлении статусов (например, прочтение пачки сообщений) — не блокирует ленту и не порождает лавину перерисовок.

## Requirements *(mandatory)*

### Functional Requirements

Внешний вид и дизайн-токены:

- **FR-001**: Система MUST приводить все поверхности мессенджера (сайдбар, окно чата, модальные окна, контекстные меню, тосты, страницы настроек) к точному соответствию утверждённому прототипу `specs/008-chat-window-styling/design/chats.html` (версионированная копия исходного `tmp/chats.html`) по типографике, сетке, отступам, палитре и фоновым паттернам; прототип — нормативный визуальный эталон, расхождения решаются в пользу прототипа для облика и в пользу существующей функциональности для поведения.
- **FR-002**: Все визуальные константы прототипа (палитра, шрифтовые роли, отступы, радиусы, тени, паттерны) MUST быть выражены единым набором дизайн-токенов, используемым всеми поверхностями; дублирование значений в обход токенов не допускается.
- **FR-003**: Типографика MUST использовать шрифты Old Standard TT (основной текст, курсивные подписи), Cormorant SC (заголовки, имена, бейджи, надписи кнопок), Anonymous Pro (поля ввода, текст сообщений, моноширинные значения) с поддержкой кириллицы и латиницы и резервными стеками на случай недогрузки.
- **FR-004**: Внешнее оформление MUST воспроизводить корпус-«машину» (золотая окантовка, панели с заклёпками, тёмные фоновые паттерны, зерно и виньетка поверх) по прототипу; при системной настройке «уменьшить движение» все анимации MUST отключаться без потери читаемости.
- **FR-005**: Контракты публичного API и доменная логика фич 004–007 MUST оставаться неизменными (0 изменений контрактов); фича добавляет только презентационный слой.

Сайдбар и главное меню:

- **FR-006**: Сайдбар MUST содержать поле поиска и список чатов; табы «Чаты»/«Контакты» MUST быть удалены.
- **FR-007**: Рядом с поиском MUST быть кнопка главного меню с пунктами «Мой профиль», «Контакты», «Создать групповой чат»; меню закрывается повторным кликом, кликом вне или Esc.
- **FR-008**: Элемент списка чатов MUST отображать: аватар (октагональный для групп), имя, превью последнего сообщения (с префиксами «Вы: » для исходящего и «Имя: » для отправителя группы; «Нет сообщений» для пустого чата), время последнего сообщения (для чата без сообщений — не отображается), бейдж непрочитанных с капом отображения «99+» начиная со 100, метку «заблокирован» для чатов с заблокированным контактом.
- **FR-009**: Порядок списка чатов MUST следовать существующему правилу упорядочивания по времени последнего события (сообщение/создание чата) без изменения.
- **FR-010**: Поиск сайдбара MUST фильтровать список чатов по имени; поиск по содержимому сообщений в объём фичи НЕ входит (фича 013).

Контакты — модальное окно:

- **FR-011**: Модальное окно «Контакты» MUST показывать список, отсортированный по отображаемому имени, затем по username, с поиском по подстроке имени/username/email без учёта регистра и оформленными пустыми состояниями («Нет контактов», «Ничего не найдено»).
- **FR-012**: Добавление контакта MUST выполняться по точному совпадению username или email без учёта регистра: совпадение найдено — контакт добавляется (или используется существующий), открывается переписка; не найдено — ошибка без создания; уже в контактах — идемпотентное поведение с уведомлением.
- **FR-013**: Действия контакта в контекстном меню «⋯» MUST включать: «Заблокировать»/«Разблокировать» (с подтверждением), «Удалить чат» (для связанного чата; контакт сохраняется) либо «Создать чат» (когда чата нет), «Удалить контакт» (с подтверждением; чат и история сохраняются); в списке отображаются пометки «заблокирован» и «чат удалён»; клик по контакту со связанным чатом открывает чат.
- **FR-014**: Все деструктивные операции (блокировка, удаление чата, удаление контакта, удаление/выход из группы) MUST требовать явного подтверждения в модальном окне с выделенной «опасной» кнопкой.

«Мой профиль»:

- **FR-015**: Модальная форма «Мой профиль» MUST показывать username и email только для чтения и переключатель «Режим инкогнито» (семантика и API фичи 007); сохранение применяет режим и подтверждается уведомлением; редактирование отображаемого имени в объём фичи НЕ входит (фича 008a).

Окно чата:

- **FR-016**: Заголовок окна чата MUST отображать аватар, имя и статус: для личного чата — статус присутствия из 007 (включая нейтральное «неизвестно» без ложного «офлайн»), для группы — число участников с корректной русской плюрализацией; кнопки заголовка ограничиваются меню настроек чата («шестерёнка»); кнопки поиска по чату (фича 013) и per-chat звука (фича 008a) в объём фичи НЕ входят и не отображаются.
- **FR-017**: Наведение на статус группового чата MUST показывать всплывающий список участников: «Вы» первым (с пометкой «администратор» при владении чатом), далее участники с пометкой «администратор» для администратора группы.
- **FR-018**: Лента сообщений MUST отображать пузыри по прототипу (исходящие — «золотая пластина», входящие — «тёмная панель», асимметричные радиусы) с аватарами, именем отправителя в групповых входящих и штампами доставки ✓ (доставлено) / ✓✓ (прочитано) с анимацией при смене статуса; существующие состояния статусов доставки 004/005 сохраняются.
- **FR-019**: Каждое сообщение MUST отображать время в формате ЧЧ:ММ из createdAt; между сообщениями разных дней MUST выводиться разделитель дат в длинном формате по прототипу.
- **FR-020**: Пагинация истории (004/005) MUST сохраняться и стилизоваться: подгрузка более старых сообщений при прокрутке вверх, корректные разделители дат и порядок на стыках страниц.
- **FR-021**: Композер MUST воспроизводить оформление прототипа (золотая рама поля, кнопка «ОТПРАВИТЬ»), отправку по Enter, ограничение длины ввода по существующему правилу, сохранение фокуса в поле при отправке кнопкой.
- **FR-022**: Для чата с заблокированным контактом композер MUST быть неактивен с поясняющей подсказкой; отправка исключена; разблокировка возвращает активность (логика блокировки 004 без изменений).
- **FR-023**: Меню «шестерёнки» чата MUST предоставлять существующие операции: для личного чата — «Добавить в контакты» (если собеседник не в контактах), «Заблокировать/Разблокировать контакт», «Удалить чат»; для группы (владелец/администратор) — «Участники», «Редактировать чат» (название, описание, состав участников), «Удалить чат»; для обычного участника — «Участники», «Выйти из чата» (ростер-действия и роли 006 без изменений).

UI-слой (без изменения API):

- **FR-024**: Аватары MUST строиться из инициалов username (две буквы) с детерминированным цветом из палитры прототипа (одно и то же имя — один и тот же цвет) и октагональной формой для групп; аватары личных чатов и контактов MUST нести presence-точку по состояниям 007 («онлайн» — зелёная со свечением, «офлайн» — тусклая, «неизвестно» — нейтральная).
- **FR-025**: Система MUST использовать единый механизм тостов: одно уведомление на экране, авто-скрытие (~3 секунды), поверх любых слоёв, с результатом каждой завершающейся операции.
- **FR-026**: Модальные окна MUST использовать единую оболочку (заголовок, формы, встроенные ошибки, кнопки обычная/основная/опасная) с закрытием по Esc и по фону (нажатие и отпускание на самом фоне, перетаскивание из окна не закрывает).
- **FR-027**: Контекстные меню (главное, контактное, меню чата) MUST позиционироваться у якоря с ограничением в пределы экрана, закрываться по клику вне и Esc, поддерживать разделители и выделение опасных пунктов.
- **FR-028**: Звуковые оповещения отправки и приёма MUST синтезироваться на клиенте без внешних аудиофайлов и без персистентной настройки (всегда включены); запрет автозвука до первого действия пользователя MUST обработываться молчаливым пропуском звука без влияния на функциональность.
- **FR-029**: На узких экранах (≤ ~900px) сайдбар MUST превращаться в выдвижной drawer с burger-кнопкой и затемнением, закрывающийся при выборе чата; на широких экранах (≥ ~901px) «машина» MUST целиком вписываться в окно без прокрутки страницы.

Состояния 005–007 и общие качества:

- **FR-030**: Статусы outbox («отправляется», «не отправлено» с повтором/удалением, баннер переполнения очереди, отсчёт ретрая флуд-лимита) и индикатор синхронизации MUST сохранять поведение 005 и быть оформлены в дизайн-систему прототипа.
- **FR-031**: Страницы настроек (наследие 004–007) MUST быть переоформлены в дизайн-систему прототипа без потери функций.
- **FR-032**: Пустые, загрузочные и ошибочные состояния окна чата и списков (нет чатов, нет сообщений, нет результатов поиска, сбой загрузки) MUST быть оформлены в едином стиле.
- **FR-033**: Любой пользовательский текст (сообщения, имена, поисковые запросы) MUST отображаться с экранированием разметки — визуальная стилизация не вводит возможности внедрения разметки пользователем.
- **FR-034**: Функциональные тесты и приёмочные сценарии фич 004–007 MUST проходить на новом UI без изменения ожиданий поведения (допустима адаптация селекторов/локаторов).
- **FR-035**: Все интерактивные элементы (главное меню, контекстные меню, модальные окна, drawer, списки чатов/контактов, композер) MUST быть полностью достижимы и управляемы с клавиатуры: логичный порядок табуляции, видимый индикатор фокуса в дизайн-системе прототипа, ловушка фокуса внутри модальных окон и drawer, возврат фокуса на инициатор после закрытия; расширенные требования доступности (WCAG-контраст, ARIA, скринридеры) в объём фичи НЕ входят.
- **FR-036**: Новый UI MUST корректно работать (функциональность и облик) в двух последних версиях Chrome, Edge, Firefox и Safari на desktop и мобильных платформах; поведение в браузерах вне матрицы не входит в объём приёмки.

### Key Entities *(include if feature involves data)*

- **Дизайн-токен**: именованная визуальная константа из прототипа (цвет, шрифтовая роль, отступ, радиус, тень, паттерн); единый источник оформления всех поверхностей.
- **Аватар**: производная UI-сущность — инициалы (2 символа из username), детерминированный цвет, форма (круг для пользователей / октагон для групп), presence-точка.
- **Разделитель дат**: производная UI-сущность от createdAt соседних сообщений ленты.
- **Тост**: одиночное короткое уведомление результата операции (текст, авто-скрытие).
- **Контекстное меню**: список действий над объектом (главное меню, контакт, чат) с привязкой к якорю и позиционированием в пределах экрана.
- **Модальная оболочка**: общий контейнер форм и подтверждений (заголовок, тело, кнопки; закрытие по фону/Esc).
- **Звуковой сигнал**: короткий синтезируемый сигнал события (отправка/приём) без настройки.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% ключевых экранов (список чатов; заголовок, лента и композер личного чата; групповой чат; модальные «Контакты», «Мой профиль», создание/редактирование группы; контекстные меню; состояния outbox/синхронизации) проходят визуальное сравнение с эталонными снимками, произведёнными по прототипу, с допуском не более ~2% отличающихся пикселей на ключевой экран.
- **SC-002**: Все существующие автоматические проверки функциональности фич 004–007 проходят на новом UI; 0 функциональных регрессий (изменения ожиданий поведения не допускаются).
- **SC-003**: Публичные API-контракты не изменены — 0 отличий контрактов до/после фичи.
- **SC-004**: Все ключевые пользовательские сценарии (отправка сообщения, добавление контакта, создание группы, блокировка/разблокировка, инкогнито, повтор неотправленного сообщения) завершаются успешно в 100% прогонов приёмочных сценариев нового UI.
- **SC-005**: На экранах шириной от ~901px «машина» полностью помещается без прокрутки страницы; на экранах до ~900px список чатов доступен через burger-drawer не более чем за 2 действия.
- **SC-006**: Текст на кириллице и латинице отображается единообразно во всех поверхностях — 0 случаев подмены шрифта внутри блока или нечитаемых символов.
- **SC-007**: 100% деструктивных операций требуют явного подтверждения; ни одна не выполняется одним кликом из списка или меню.
- **SC-008**: 100% интерактивных элементов достижимы и управляемы с клавиатуры (табуляция, Enter/Space, Esc), фокус видим, после закрытия меню/модального окна/drawer фокус возвращается на инициатор — проверяется приёмочным сценарием «без мыши».
- **SC-009**: 100% ключевых приёмочных сценариев фичи проходят в каждом браузере матрицы FR-036 (Chrome, Edge, Firefox, Safari — последние 2 версии, desktop и мобильные).
- **SC-010**: Анимации и прокрутка ленты выполняются на 60 fps без деградации; первый рендер экрана чата — не более 1 с; лента остаётся плавной при 1000+ сообщений в загруженной истории (измерение на браузере матрицы FR-036).

## Assumptions

- Прототип — утверждённый нормативный эталон облика (типографика, сетка, отступы, палитра, паттерны, микроанимации); версионированная копия хранится в `specs/008-chat-window-styling/design/chats.html`; конкретный способ визуальной регрессии (скриншотные тесты, storybook) выбирается в `plan.md`.
- Кнопки заголовка чата «поиск по чату» (фича 013) и «звук per-chat» (фича 008a) не отображаются до реализации своих фич; в 008 заголовок содержит только меню «шестерёнку» — их появление входит в 008a/013.
- «Мой профиль» в 008 не содержит редактируемого поля имени (отображаемые имена — 008a); инициалы аватаров в 008 строятся из username; переименование контакта (alias) также 008a и в контекстное меню контакта не входит.
- Цвет аватара вычисляется детерминированно из username по палитре прототипа (без изменения API); совпадение цветов у разных пользователей допустимо.
- Форматы отображения: время ЧЧ:ММ, даты — длинный формат русской локали по прототипу; данные времени берутся из существующего поля createdAt контрактов.
- Звук всегда включён и не настраивается (переключатель и персистентность per-chat — 008a); «беззвучная» среда не влияет на визуальные уведомления.
- Поиск сайдбара в 008 фильтрует список чатов по имени; поиск по сообщениям — 013, typing-индикатор, lastSeen, отображаемые имена — 008a: всё это в прототипе есть, но в объём 008 не входит.
- Границы «узких» экранов (~900px, ~480px) следуют прототипу; точные контрольные точки фиксируются в `plan.md`.
- Существующие страницы настроек сохраняют свои функции и адресацию; переоформление не меняет их маршруты и поведение.
