**Branch**: `008-chat-window-styling` | **Date**: 2026-10-03

Источники: нормативный прототип `specs/008-chat-window-styling/design/chats.html` (1749 строк, побайтово = `tmp/chats.html`), спека [spec.md](./spec.md) с Clarifications, код `frontend/src` (фичи 004–007), `contracts/openapi.yaml` 0.7.0, CI `.github/workflows/ci.yml`.

## §A. Подключение шрифтов (FR-003)

**Decision**: Самохостинг через npm-пакеты `@fontsource/old-standard-tt` (400/700 + italic 400), `@fontsource/cormorant-sc` (400/600/700), `@fontsource/anonymous-pro` (400/700 + italic 400) — все версии 5.3.0 существуют в реестре, woff2-сабсеты cyrillic+latin лежат в пакете и бандлятся Vite в `dist/assets` со своего origin (ровно так уже работают `@fontsource/cinzel`/`eb-garamond` в auth). Импорты — в новом `frontend/src/theme/fonts.css` с резервными стеками: serif → `'Old Standard TT', 'Times New Roman', serif`; заголовки → `'Cormorant SC', 'Georgia', serif`; моно → `'Anonymous Pro', 'Courier New', monospace`.

**Rationale**: Требование FR-003 — woff2 в репозитории (lock-файл фиксирует артефакты пакета), отдача со своего origin, CDN запрещён; @fontsource — уже принятый в проекте паттерн, нулевой рантайм-код, сабсеты покрывают кириллицу+латиницу (SC-006).

**Alternatives considered**: (1) ручное скачивание woff2 в `frontend/public/fonts/` + `@font-face` руками — больше контроля, но дублирует механику fontsource и ломает консистентность; (2) Google Fonts CDN — прямо запрещён FR-003; (3) subset-генерация (glyphhanger/subfont) — преждевременная оптимизация (YAGNI), fontsource-сабсеты уже сегментированы по языкам и грузятся по `unicode-range`.

## §B. Визуальная регрессия (SC-001, допуск ~2% пикселей)

**Decision**: Ввести dev-зависимость `@playwright/test`; новый набор `frontend/tests/visual/` (скрипт `test:visual`): Chromium, эталонная desktop-ширина прототипа (1440×900, окно «машины» max-width 1360px) + мобильные состояния 900×700 (открытый burger-drawer) и 480×800 (окно чата). Эталонные снимки ключевых экранов производятся по прототипу `design/chats.html` (фиксируются в репозитории как baseline), снимки реализации сравниваются с допуском `maxDiffPixelRatio ≈ 0.02`. Для сопоставимости данных тесты запускают страницу мессенджера на fixture-данных, повторяющих демо-набор прототипа (те же имена/цвета/времена через MSW-подобный стаб или тестовый режим с fixture-пропсами — фиксируется в tasks.md).

**Rationale**: SC-001 требует числового порога «не более ~2% отличающихся пикселей» — это screenshot-diff; Playwright `toHaveScreenshot` — стандарт с built-in сравнением и `maxDiffPixelRatio`. Достиимость порога обеспечивается тем, что CSS прототипа переносится в токены/`machine.css` дословно (§C) — реализация рендерит те же стили на тех же макетных размерах. Baseline из прототипа (а не из себя) — прямое исполнение формулировки SC-001 «эталонные снимки, произведённые по прототипу». Матрица SC-009 (4 браузера × desktop/mobile) — приёмочная, прогоном функциональных сценариев; визуальный diff в CI достаточно гонять на Chromium (стабильные снимки; шрифтовый рендер Firefox/Safari даёт шум антиалиасинга).

**Alternatives considered**: (1) Storybook + test-storybook — тяжёлая новая инфраструктура ради 10 экранов; (2) Percy/Chromatic — внешний SaaS, CI-зависимость и секреты (конфликт с самодостаточностью репо); (3) только ручное сравнение — не измеримо, SC-001 требует числовой порог; (4) jsdom+pixelmatch без браузера — jsdom не рендерит CSS.

## §C. Архитектура CSS и перенос облика прототипа (FR-001, FR-002)

**Decision**: Три файла в `frontend/src/theme/`: `fonts.css` (§A), `tokens.css` (`:root`-переменные из блока 1 прототипа: палитра `--gold…`, `--panel-bg`, `--input-bg`, `--cream…`, `--muted…`, `--ok/--err`, паттерны `--pat-main`/`--pat-msg` как data-URI SVG, шрифтовые роли), `machine.css` (корпус `.machine`/окантовка/панели/заклёпки, зерно+виньетка через body::before/after, скроллбары, burger/backdrop, адаптив 900/480, prefers-reduced-motion-глобал по прототипу). Стили поверхностей (сайдбар, чат, пузыри, композер, модали, меню, тост) — переносятся из прототипа класс-в-класс и живут в них же/theme, заменяя действующие стили мессенджера в `index.css`; auth-страницы не затрагиваются (своя тема). Существующие тестовые классы-хуки (`chat-item`, `message-list`, `chat-panel-search`, `dialog-menu`…) сохраняются как обёртки/дополнения к прототипным классам, чтобы минимизировать адаптацию тестов (FR-034).

**Rationale**: Прототип — нормативный эталон (FR-001: «расхождения решаются в пользу прототипа»); перенос CSS дословно — единственный способ уложиться в 2% пикселей (§B) и соблюдать FR-002 (значения только через токены, паттерны — data-URI-переменные). Прототипные CSS-селекторы (`.msg.me .bubble` и т.п.) реализуются в React-компонентах теми же классами.

**Alternatives considered**: (1) Tailwind/CSS-модули — переписывание нормативных стилей «переводчиком» внесёт расхождения с эталоном и нарушит дословность; (2) CSS-in-JS — рантайм-оверхед против бюджетов SC-010; (3) оставить всё в одном `index.css` — файл уже 1276 строк, добавка ~700 строк утопит поддерживаемость.

## §D. Навигация: табы → главное меню + модальные окна (FR-006–015) и миграция тестов

**Decision**: `ChatListPanel` лишается табов; в search-row встраивается `MainMenuButton` (контекстное меню у якоря: «Мой профиль», «Контакты», «Создать групповой чат»). Контакты — `ContactsModal` на `ModalShell`: поиск по имени/username/email (client-side, как сейчас в ContactList + email), сортировка displayName→username (`localeCompare('ru')` как в прототипе), пометки «заблокирован»/«чат удалён», kebab-меню «⋯» (ContextMenu) с действиями FR-013; добавление контакта — точный поиск №19 (`searchUsers` уже lower-case точное совпадение) с подтверждением по прототипу (addForm → confirm «Добавить контакт»). «Мой профиль» — `ProfileModal` (№38 GET/PUT presence settings, username/email readonly из `GET /users/me`). `ContactList`/`UserSearchBox` как отдельные секции сайдбара удаляются (функции мигрируют в модаль). `CreateGroupDialog` становится модальной формой по прототипу (grpForm). `GroupInfoPanel`/`GroupCard` под заголовком заменяются `ChatGearMenu` (шестерёнка) → модали «Участники»/«Редактировать чат» (membersForm/grpEditForm); `MemberList`, `AddMembersPicker`, ростер-хуки №31–35 переиспользуются без изменений логики. `ConfirmDialog` переводится с нативного `<dialog open>` на `ModalShell`+danger-кнопку (FR-014, SC-007).

**Rationale**: Прямое исполнение US2/FR-006–015 и структуры прототипа (mainMenu/contactsForm/profileForm/grpForm/grpEditForm/membersForm/confirmForm — единая модальная оболочка, восемь форм). Все операции 004–007 сохраняют свои API-вызовы и семантику — меняется только точка входа (SC-004). Пустое состояние после удаления открытого чата — «Чат не выбран» без автоперехода (Clarification).

**Alternatives considered**: (1) оставить список контактов в сайдбаре под меню — прямо противоречит FR-006 и прототипу; (2) вложенные модали поверх модалей — запрещено edge-case'ом («модальная оболочка переключает форму без наложения фонов»): реализуем переключением формы внутри одной оболочки, как в прототипе (`showForm`); (3) отдельные маршруты `/contacts` — усложнение и отклонение от прототипа.

**Миграция тестов (SC-002, FR-034)**: поведенческие ожидания 004–007 не меняются; адаптация там, где меняется DOM: тесты табов `ChatListPanel` → переписываются на меню+модаль; тесты `ContactList`/`UserSearchBox` → на `ContactsModal`; `GroupInfoPanel.*` → на модали; тексты кнопок («Действия» → шестерёнка) — обновляются локаторы. Существующие тексты статусов («доставлено», «прочитано», «отправляется», «не отправлено», «Повторить», «Удалить») сохраняются в aria-label/визибл-текстах.

## §E. Аватары: инициалы и детерминированный цвет (FR-024, Clarification 2026-10-03)

**Decision**: `ui/avatar.ts`: `initialsOf(source)` — по алгоритму прототипа: первые буквы первых двух слов (одиночное слово — одна буква); source = username для пользователей (включая peer личного чата и «Вы»), title для групп; при переименовании группы аватар пересчитывается сам (derivация на лету). `colorOf(source)` = `PALETTE[hash(source) mod PALETTE.length]`, где PALETTE — палитра прототипа `['#c2622a','#7a5a8b','#4e7a8b','#5e8b7e','#8b3a3a','#a08830']` (GROUP_COLORS), hash — простая детерминированная сумма code units (FNV-1a 32-bit), без персистентности. Форма: круг (пользователи) / октагон через `clip-path` (группы). Presence-точка на аватарах личных чатов/контактов: из `presenceStore` (007) — online → зелёная с мерцанием (`flick`), offline → тусклая (`.off`), unknown → нейтральная (без ложного «офлайн», семантика 007).

**Rationale**: Clarification: источник — username/название группы, цвет детерминирован тем же значением; палитра взята из прототипа (норматив); совпадения цветов/инициалов у разных сущностей допустимы (edge case спеки). FNV-1a — стабилен, быстр, распределение по 6 цветам достаточно равномерно.

**Alternatives considered**: (1) MD5/SHA — тяжеловесно для выбора из 6 цветов; (2) сохранять цвет при создании чата (снапшот) — нарушает Clarification про пересчёт при переименовании и добавляет состояние; (3) вводить расширенную палитру вне прототипа — нарушение FR-001/FR-002.

## §F. Звук приёма: WebAudio-звоночек и коалесцирование (FR-028, US5)

**Decision**: `ui/sound.ts` — синтез по прототипу: `bellTone` с партиалами 1 : 2.76 : 5.4 (sine + экспоненциальное затухание), «динь-динь» (1050 Гц t=0, 1400 Гц t+0.1 с); ленивый `AudioContext`, `resume()` при suspended, все ошибки — молчаливый `try/catch` (запрет автозвука до первого действия → пропуск без поломок). Подключение: (а) реальное время — подписка `useRealtime().onMessageCreated(chatId=null, e => e.message.senderId !== me → play())` — один сигнал на событие, для любого чата включая фоновые; (б) массовая доставка — в `useSync`/`applySyncUpdate`-пути счётчик входящих за цикл синхронизации → один сигнал, если ≥1 (коалесцирование); (в) начальная загрузка истории и пагинация — сигнала нет. Сигнала отправки нет вообще (Clarification). Настроек и персистентности нет — «всегда включено».

**Rationale**: Прототип содержит готовый синтез без аудиофайлов (требование FR-028 «без внешних аудиофайлов»); точки интеграции identified в исследовании кода: `useRealtime` (realtime-события) и цикл catch-up `useSync` (batch) — единственные пути доставки входящих. Коалесцирование «один на пакет» реализуется флагом «сигнал уже сыгран в этом sync-цикле».

**Alternatives considered**: (1) `<audio>` + mp3-файл — нарушает «без внешних аудиофайлов»; (2) звук в `useChatList` на изменение превью — пропускает фоновые чаты и порождает дубли источников; (3) очередь сигналов с троттлингом — не требуется: уже один на событие/пакет.

## §G. Производительность ленты и списка (SC-010, SC-011)

**Decision**: Без новых библиотек. Пузыри и строки списков — `React.memo` с минимизацией пропов; строки ленты и списка чатов получают `content-visibility: auto` + `contain-intrinsic-size` (дешёвое браузерное виртуализирование offscreen-узлов); анимации — только `transform/opacity` (pop, tickStamp, flick по прототипу); анимация штамповки при массовом обновлении статусов — одним CSS-классом на изменившихся узлах (без перерисовки списка, водяные знаки уже монотонные). Изображение зерна/виньеток — фиксированные `body::before/after` (один композиционный слой, не анимируются). Метрика: задача-измерение в tasks.md (Playwright trace / DevTools на 1000+ сообщений и 200+ чатах) — если 60 fps не достигается, виртуализация (`@tanstack/react-virtual`) вводится отдельной задачей с обоснованием.

**Rationale**: YAGNI (конституция VII): `content-visibility` решает типовой случай длинной ленты без полосы прокрутки-анкеров пагинации (виртуализация конфликтует с текущим scrollHeight-анкером `loadOlder` и потребует переделки пагинации). Бюджеты SC-010/011 — измеримые, фиксируются проверкой.

**Alternatives considered**: (1) сразу react-window/virtual — риск сломать пагинацию-анкер 005 и потеря простоты; (2) пагинация «окном» — меняет поведение 005 (запрещено SC-002); (3) Web Animations API для штампов — CSS-анимации прототипа уже декларативны и снимаются reduced-motion.

## §H. Адаптив, клавиатура и visual viewport (FR-029, FR-035, SC-005, SC-008)

**Decision**: Breakpoint'ы прототипа: `≤900px` — sidebar фиксированный drawer (transform, backdrop, закрытие по выбору чата/клику по затемнению/повторному burger), `≥901px` — `html,body{overflow:hidden}`, машина `height:calc(100dvh - 36px)` без прокрутки страницы; `≤480px` — компактная кнопка отправки, пузырь до 84% ширины. Клавиатура: фокус-ловушка и возврат фокуса — в `ModalShell` и drawer; меню (`ContextMenu`) — ArrowUp/Down/Enter/Space/Esc; порядок закрытия слоёв по Esc сверху вниз: контекстное меню → модаль → drawer (edge case); видимый focus-ring в дизайн-системе (`:focus-visible` золотая обводка). Экранная клавиатура: `100dvh` + слушатель `visualViewport` (CSS-переменная `--vvh/--vvo` на body) — композер остаётся над клавиатурой, лента сжимается, прокрутки страницы нет.

**Rationale**: Прототип уже содержит media-запросы и burger-механику — перенос дословный (§C); dvh + visualViewport — стандартный паттерн мобильных чатов, покрывает iOS Safari behavior (матрица FR-036); requirements FR-035 — клавиатура обязательна, ARIA/контраст — нет.

**Alternatives considered**: (1) `interactive-widget=resizes-content` в viewport-мета — поддержка неполная (iOS < 16.4 игнорирует), dvh+JS надёжнее; (2) отдельные мобильные маршруты — усложнение.

## §I. Тосты, модали, меню — единые примитивы (FR-025–027)

**Decision**: `Toast` — ToastProvider с одиночным слотом (fixed, z-99 поверх модалей), авто-скрытие 3000 мс, новый тост заменяет предыдущий; используется всеми завершающимися операциями (US3-4). `ModalShell` — по прототипу `.modal-back/.modal`: закрытие по фону только «press+release на фоне» (mousedown+click на самом фоне, перетаскивание не закрывает), Esc, фокус-ловушка, возврат фокуса на инициатор; переключение форм внутри одной оболочки без наложения фонов. `ContextMenu` — fixed у якоря, clamp в пределы экрана (формулы прототипа), клик-вне/Esc, разделители `ctx-sep`, danger-пункты. Members-tip (наведение на статус группы) — tooltip по прототипу («Вы» первым, пометки «администратор»), с клавиатурным доступом по фокусу.

**Rationale**: Прототип содержит готовую механику всех трёх примитивов (toast/modal/ctx-menu + позиционные формулы) — перенос дословный; единые примитивы = FR-025/026/027 и SC-007/008 без дублирования. Длительность тоста 3000 мс — по FR-025 «~3 секунды» (значение прототипа 2600 мс — демо-число, спецификация главнее для поведения).

**Alternatives considered**: (1) библиотека radix/headlessui — тяжёлые абстракции против дословности прототипа и YAGNI; (2) нативный `<dialog>` — лишает контроля закрытия-по-фону и стилей анимации прототипа.

## §J. Время и разделители дат (FR-019, FR-016)

**Decision**: `ui/time.ts`: время — `Intl.DateTimeFormat('ru-RU', {hour:'2-digit',minute:'2-digit'})` из `createdAt` (24-ч «ЧЧ:ММ» как `en-GB`-паттерн прототипа, но ru-локаль даёт тот же формат); разделитель дат — длинный формат прототипа: `{day:'numeric', month:'long'}` («19 сентября»; с годом `{year:'numeric'}` при отличии от текущего — уточняется визуально по прототипу, в прототипе год не выводится — принимаем без года во всех случаях, кроме несовпадения года — фиксируется в contracts/design-tokens.md как поведение). Разделитель вставляется при смене календарного дня между соседними сообщениями, ровно один раз на стыке страниц пагинации (сравнение с первым элементом новой страницы). Плюрализация участников — `pluralRu` из прототипа.

**Rationale**: Все данные уже в контрактах (`createdAt`); Intl — без зависимостей; edge cases (полночь, стык страниц) покрываются сравнением дат соседних элементов.

**Alternatives considered**: date-fns/dayjs — одна функция форматирования, библиотека не нужна (YAGNI).

## §K. Состояния 005–007 в новом облике (FR-030–032)

**Decision**: Поведение без изменений, оформление в токены: «отправляется»/«не отправлено» (Повторить/Удалить) на пузырях; баннер переполнения очереди и индикатор синхронизации — стилизуются по дизайн-системе (позиции сохраняются: сайдбар/заголовок); отсчёт ретрая флуд-лимита — строка статуса над композером («Повтор через N с», тикает один элемент по головной ожидающей записи retryAt открытого чата, ввод не блокируется); ввод блокируется только при заблокированном контакте (подсказка в placeholder/строке статуса). Пустые/загрузочные/ошибочные состояния («Нет сообщений», «Ничего не найдено», «Чат не выбран», сбой) — единый стиль. Страницы настроек `/settings/*` — переоформление токенами, маршруты и функции без изменений (FR-031).

**Rationale**: Прямое требование US4/FR-030–032 и Clarifications (отсчёт в композере, не на пузырях; ввод активен при флуд-лимите). Источник отсчёта `retryAt` уже есть в outbox-записях 005.

**Alternatives considered**: отсчёт на пузыре — отвергнут Clarification; полная блокировка композера при флуд-лимите — отвергнута (поведение 005 без изменений).
