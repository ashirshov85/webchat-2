# Data Model: Стилизация окна чата «Aethergram»

**Branch**: `008-chat-window-styling` | **Date**: 2026-10-03

Фича не вводит durable-сущностей и не меняет контракты API (SC-003, FR-005). Все новые сущности — **производные UI-сущности**, вычисляемые на лету из данных существующих контрактов (`ChatListItem`, `Message`, `GroupView`, presence-снапшоты №36) и локального outbox (005). Ниже: (1) новые UI-сущности, (2) производные view-модели существующих сущностей, (3) затрагиваемые машины состояний. Нормативные значения констант — [contracts/design-tokens.md](./contracts/design-tokens.md), поведение — [contracts/ui-behavior.md](./contracts/ui-behavior.md).

## 1. Новые UI-сущности

### 1.1 DesignToken (Дизайн-токен)

| Поле | Тип | Описание |
|---|---|---|
| name | string | CSS-переменная `:root` (например `--gold`, `--pat-main`, `--font-role-heading`) |
| value | string | Значение из прототипа (цвет/градиент/data-URI SVG-паттерна/шрифтовый стек) |
| usage | string[] | Поверхности-потребители (все стили — только через токены, FR-002) |

Правила валидации: набор токенов — точная проекция блока «1. БАЗА, ПЕРЕМЕННЫЕ И ПАТТЕРНЫ» прототипа; дублирование литеральных значений вне `tokens.css` не допускается (lint-правило просмотра в tasks.md).

### 1.2 Avatar (Аватар) — производная

Вычисляется чистой функцией из одного источника (FR-024, Clarification):

| Поле | Тип | Derivation |
|---|---|---|
| source | string | `username` (пользователи: peer, контакт, «Вы», отправитель) либо `title` (групповой чат) |
| initials | string (1–2 буквы) | `initialsOf(source)`: первые буквы первых двух слов, uppercase; одиночное слово — одна буква |
| color | string (hex) | `colorOf(source)` = `PALETTE[fvn1a32(source) mod 6]`, `PALETTE` — палитра прототипа (6 цветов, см. design-tokens) |
| shape | `'circle' \| 'octagon'` | circle — пользователи; octagon (clip-path 30/70%) — групповые чаты |
| presenceDot | `'online' \| 'offline' \| 'unknown' \| null` | из presenceStore 007 (только аватары личных чатов/контактов); null — группы, собственный аватар, отправители в ленте |

Правила: детерминизм — одно и то же значение source даёт одинаковые initials+color (без персистентности); переименование группы → аватар пересчитывается автоматически; совпадения цветов/инициалов у разных сущностей допустимы (различие — именем). «Неизвестно» ≠ «офлайн»: до получения данных presence — нейтральная точка (семантика 007, edge case).

### 1.3 DateDivider (Разделитель дат) — производная

| Поле | Тип | Derivation |
|---|---|---|
| key | string (ISO-дата дня) | календарный день `createdAt` сообщения |
| label | string | `Intl('ru-RU', {day:'numeric', month:'long'})`, при отличии года от текущего — с годом |

Правила: вставляется между сообщениями A (ранее) и B (позднее) ⟺ `день(A.createdAt) ≠ день(B.createdAt)`; ровно один на стыке страниц пагинации (сравнение с первым сообщением догруженной страницы); полночь между сообщениями одного сеанса — новый разделитель; пустая лента — разделителей нет.

### 1.4 Toast (Тост)

| Поле | Тип | Описание |
|---|---|---|
| id | number | монотонный счётчик (для замены предыдущего) |
| text | string | результат операции (русский язык, без i18n) |
| visible | boolean | жизненный цикл: show → auto-hide через 3000 мс |

Ограничения: одиночный слот на приложение (новый тост заменяет видимый — FR-025); позиция — поверх любых слоёв (z-99 над модалью); закрывается только таймером (pointer-events: none). Источники: все завершающиеся операции US2/US3 (ровно один тост на операцию — US3-4).

### 1.5 ContextMenu (Контекстное меню)

| Поле | Тип | Описание |
|---|---|---|
| anchor | DOMRect | якорь (кнопка меню/«⋯»/«шестерёнка») |
| items | MenuItem[] | `{label, onSelect, danger?, sepBefore?}` |
| placement | {left, top} | формулы прототипа: у якоря + clamp в пределы экрана (8px поля) |

Экземпляры (все на одном примитиве): главное меню (FR-007), контактное «⋯» (FR-013), меню чата «шестерёнка» (FR-023). Опасные пункты — визуально выделены; разделители между группами действий.

### 1.6 ModalShell (Модальная оболочка)

| Поле | Тип | Описание |
|---|---|---|
| formId | enum | `contacts \| add-contact \| create-group \| group-edit \| group-members \| profile \| confirm` |
| title | string | заголовок оболочки |
| stackPolicy | — | одна оболочка на приложение; переключение formId внутри без наложения фонов (edge case) |

Формы-обитатели и их контракты — см. ui-behavior §3.

### 1.7 SoundSignal (Звуковой сигнал)

| Поле | Тип | Описание |
|---|---|---|
| kind | `'receive-bell'` | единственный вид; сигнала отправки нет (FR-028) |
| trigger | `'realtime' \| 'sync-batch'` | realtime — 1:1 с событием; sync-batch — 1 на цикл массовой доставки (коалесцирование) |
| playback | — | WebAudio-синтез (партиалы 1:2.76:5.4, «динь-динь»); при запрете автозвука — молчаливый пропуск |

Исключения (сигнала нет): начальная загрузка истории, пагинация, отправка, собственные события.

## 2. View-модели существующих сущностей (рестайлинг без изменения API)

### 2.1 ChatListItemView (список чатов, FR-008–010)

| Поле | Источник в контракте | Отображение |
|---|---|---|
| avatar | Avatar(peer.username \| group.title) | + presenceDot (direct) |
| name | peer.username / group.title | усечение с многоточием, title-подсказка |
| preview | lastMessage + currentUserId | префикс «Вы: » (исходящее direct/группа) или «Имя: » (входящее группы); «Нет сообщений» при null |
| time | lastMessage.createdAt | ЧЧ:ММ; пусто при отсутствии сообщений |
| badge | unreadCount (int64) | число; при ≥100 — «99+» (UNREAD_CAP — рендер) |
| blocked | blockedByMe | метка «заблокирован» (и заморозка бейджа — семантика 005) |
| order | lastMessage.createdAt DESC (без изменений) | FR-009 |

Фильтр поиска — по `name` (client-side, FR-010; поиск по сообщениям — фича 013).

### 2.2 MessageBubbleView (лента, FR-018–020)

| Поле | Источник | Отображение |
|---|---|---|
| side | senderId === currentUserId | me → «золотая пластина», them → «тёмная панель», асимметричные радиусы |
| senderName | sender в группе (входящие) | каптиализированная строка над текстом; direct — нет |
| text | Message.text | экранирование React (FR-033), `white-space: pre-wrap`, break-word |
| time | createdAt | ЧЧ:ММ в ножке пузыря |
| tick | вычисление 004–007 без изменений | outbox sending → «отправляется»; подтверждено → ✓; seq ≤ peerRead/othersRead → ✓✓; failed → «не отправлено» + Повторить/Удалить |
| avatar | Avatar(sender.username) | слева/справа от пузыря; своё — из своего username |

Штамп ✓/✓✓: анимация «штамповки» только при смене статуса (tickStamp), массовое обновление — без лавины перерисовок (§research G).

### 2.3 ChatHeaderView (заголовок, FR-016–017)

| Поле | Источник | Отображение |
|---|---|---|
| avatar | Avatar(как 1.2) | direct — circle+presence, group — octagon |
| status | direct: presenceStore (online/offline/unknown); group: memberCount | direct: лампа + «В сети»/нейтральное «неизвестно» (без ложного «офлайн»); group: `pluralRu` «N участников» |
| membersTip | GroupView.members + myRole | hover/focus статуса группы: «Вы» первым (+«администратор» при владении), далее участники с пометкой «администратор» |
| actions | ChatGearMenu (FR-023) | единственная кнопка заголовка; поиск (013) и per-chat звук (008a) не отображаются |

### 2.4 ComposerView (композер, FR-021/022, FR-030)

Состояния: `active` (обычный) / `blocked` (заблокированный контакт: disabled + подсказка — единственная блокировка ввода) / `active+retry-countdown` (флуд-лимит: строка «Повтор через N с» из головной retryAt-записи outbox открытого чата, ввод активен, пузырь ожидания — статичное «отправляется»). Отправка: Enter или «ОТПРАВИТЬ»; кнопка не забирает фокус (mousedown preventDefault); лимит длины — существующая валидация 004.

### 2.5 Остальные поверхности

- **ContactsView (модаль, FR-011–013)**: список контактов + `flags[]` («заблокирован», «чат удалён»), сортировка displayName→username, фильтр name/username/email case-insensitive; действия «⋯» — ContextMenu 1.5.
- **GroupFormsView (модали, FR-023)**: create (title/description/участники из контактов), edit (title/description/состав — ростер 006), members (просмотр + ростер-действия по ролям) — на данных №27–35 без изменений логики.
- **ProfileView (модаль, FR-015)**: username/email readonly (`GET /users/me`), incognito-флажок (№38), сохранение → тост.
- **Состояния устойчивости (FR-030)**: SyncIndicator, QueueOverflowBanner, ErrorBanner — те же данные/события, новая стилизация.
- **Empty/загрузка/ошибки (FR-032)**: «Чат не выбран» (после удаления открытого чата/выхода из группы — без автоперехода), «Нет сообщений», «Ничего не найдено», «Диалогов пока нет», сбой загрузки.

## 3. Машины состояний (затрагиваемые)

### 3.1 Слои интерфейса и Esc (edge case «стекирование»)

```
Слои (снизу вверх): machine < drawer(z-40) < backdrop(z-35*) < modal(z-47) < ctx-menu(z-55)/members-tip(z-56) < grain(z-50, декор) < toast(z-99)
Esc закрывает строго верхний активный: ctx-menu/members-tip → modal → drawer (→ выход из поиска сайдбара)
```

Drawer (≤900px): `closed → open` (burger) `→ closed` (выбор чата / клик по затемнению / повторный burger / Esc, если выше нет слоёв).

### 3.2 Тост (1.4)

`hidden → visible(text, id=N) → [таймер 3000 мс | новый тост id=N+1] → hidden`. Новое событие в visible → мгновенная замена текста + перезапуск таймера.

### 3.3 Модальная оболочка (1.6)

`closed → open(formId=X)`; переходы `open(X) → open(Y)` — переключение формы внутри оболочки (подтверждение поверх формы — без второй подложки); `open → closed` — Esc / фон (press+release на фоне) / «Отмена» / успех submit; фокус: инициатор → ловушка в форме → возврат на инициатора.

### 3.4 Outbox/доставка — WITHOUT CHANGES (005)

Статусы «отправляется / не отправлено / доставлено / прочитано», ретраи, `retryAt`, вытеснение — семантика 005 сохраняется (SC-002); меняется только отображение (пузыри, штампы, строка статуса композера).

## 4. Хранилища

Без изменений: server (PG/Redis), localStorage (`outbox.v1`, сессия). Палитра/паттерны/тексты — константы кода (не персистентны); звук — без состояния (всегда включён, FR-028).
